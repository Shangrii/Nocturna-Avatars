<diagnosis>
## Root cause of the invisible footer (evidence-based, from code)

**It is a stacking/paint-order bug, not a color bug.** The footer has an opaque background of its own (`chrome.css:286-293` → `.footer { background: var(--color-ink); border-top: 1px solid var(--color-border); }`), so "navy on navy" is ruled out. What happens:

1. `BaseLayout.astro:69` — `<main transition:animate={glitchWipe}>`. Astro's ClientRouter assigns a `view-transition-name` to `<main>`. Per spec, any non-`none` `view-transition-name` **forces the element to create a stacking context** (and paint atomically).
2. `ServicesPage.astro:45` and `TermsPage.astro:37` render `<NightBackground fixed />` **inside `<main>`** (pages mount into the default slot). `night-sky.css:23-37` — `.night-bg--fixed` is `position: fixed; inset: 0; z-index: -1;` with an **opaque** `background: var(--color-ink)` plus the 12-layer `.night-sky` field, covering the full viewport at every scroll position.
3. Because `<main>` is a stacking context, `z-index: -1` only places the night field behind **main's own content** — it cannot escape below main's siblings. Main paints as one atomic unit in the positioned/stacking-context phase (equivalent to z-index 0).
4. `BaseLayout.astro:75` — `<Footer>` is a **static, non-positioned sibling with no z-index** rendered after `</main>`. Static in-flow content paints in an *earlier* phase than positioned/stacking-context boxes (CSS 2.1 Appendix E), so main's atomic layer — including the full-viewport opaque night field — paints **on top of the footer**.
5. Consistency check: Nav and FloatingCTA survive because they are `position: fixed` with explicit z-indexes (they paint above main); only the footer, the sole z-index-less chrome element, gets buried. Gallery is unaffected (non-fixed `.night-bg` is `position: absolute` scoped to the gallery section); Home has no NightBackground. This exactly matches the reported symptoms.

**Fix:** make `.footer` a positioned box at stacking level 0 (`position: relative; z-index: 0;`). It then paints in the same phase as main; equal stacking level resolves by DOM order, and the footer comes after `</main>`, so it paints above the fixed night field. On Home/Gallery this is a no-op (nothing full-viewport lives inside main there, footer has no negative-z descendants and nothing anchors to it). It is also robust in browsers without View Transitions (where main forms no stacking context and the bug never manifests).
</diagnosis>
