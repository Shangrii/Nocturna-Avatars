### CR-06: Ink/Paper Color Delta — Confirmed Blocker

The code review flag CR-06 ("paper/ink color delta is imperceptibly small") is confirmed by measurement:

- `--color-ink: #0a0c14` — luminance 0.0038
- `--color-paper: #11141f` — luminance 0.0072

Contrast ratio between these two surfaces: **1.063:1**

For context, WCAG AA requires 4.5:1 for text and the practical perception threshold for distinguishing two adjacent surfaces is roughly 1.3:1+. At 1.063:1 these two colors are visually the same shade of near-black under typical display conditions.

**History:** The SUMMARY.md documents that `--color-paper` was iterated from bright off-white → warm espresso (#241d15) → cooler dark charcoal (#11141f) across UAT passes. The final iteration went too dark — the hue shift from warm to cool exists (navy L*≈3.4, paper L*≈7.2 in CIE L* space) but is too subtle at those absolute luminance levels to register as a distinct section background.

**Downstream effect:** Because `--color-red-on-paper` was selected for legibility on an earlier (lighter) paper value and then the paper was darkened, the red token was not updated to match. Brand red `#c0192c` was legible on warm espresso `#241d15` (contrast ~4.1:1, borderline) but fails on the cooler dark `#11141f` (2.987:1).

### Human Verification Required

#### 1. Paper color decision

**Test:** Review the ink/paper palette and decide the fix direction before the re-fix plan runs.
**Expected:** Three options — (a) Revert paper to warm espresso (e.g. #1e1610, distinct warm-dark that pairs with cool navy); (b) Use a dark mid-tone that clearly separates (e.g. #1c1928, purple-dark); (c) Revert to the original editorial bright paper (#f0eae4) — maximum visual impact, requires flipping on-paper text to near-black. Option (c) was the original spec intent ("ink/paper rhythm" implies a real contrast inversion); options (a)/(b) are the "both-dark" aesthetic.
**Why human:** This is a design direction call that affects the entire site aesthetic. The fix value should be chosen by the user.

#### 2. Red-on-paper fix value

**Test:** Once the paper color is decided, confirm the red-on-paper accent is legible (section tags, terms block numbers, workflow step numbers).
**Expected:** If paper is lightened significantly, brand red `#c0192c` may clear AA or come close. If paper stays very dark, a lighter red tint similar to `--color-red-on-ink` (`#e84a5e`, 5.18:1 on ink-level darks) will be needed.
**Why human:** The value depends on the paper fix decision above; the trade-off between brand red fidelity and AA compliance requires user judgment.

### Gaps Summary

Two blockers prevent the phase goal from being declared achieved:

**Gap 1 — Ink/paper rhythm imperceptible (SC-2):** The `--color-paper` token was iterated to `#11141f` during UAT, producing a 1.063:1 contrast ratio against `--color-ink: #0a0c14`. The editorial section rhythm — the central visual innovation of this redesign — does not manifest on screen. The code structure for the rhythm (`.section--surface`, alternating sections) is fully wired and correct; only the color values need adjustment.

**Gap 2 — Red-on-paper small text fails AA (PLAT-04/SC-6):** `--color-red-on-paper: #c0192c` achieves 2.987:1 on `#11141f` (the dark paper field), failing WCAG AA for normal text (4.5:1) and large text (3:1). This affects section tags, workflow step counters, terms block numbers, and add-on titles in paper sections — the exact elements that carry the editorial visual language. The fix is tightly coupled to Gap 1: the paper color must be resolved first, then red-on-paper verified.

Both gaps share a root cause: the paper color was darkened past the threshold where the original red-on-paper choice remained valid. The fix is two color token value changes in `src/styles/theme.css`.

**What passed:** The type system (Space Grotesk display, Space Mono labels, graffiti wordmark accent) is fully implemented and wired. The cursor is gone. Tailwind v4 @theme foundation is solid. The landing reorder (featured-first) is correct. The Abrir Ticket path is reachable on every page. Chrome is fully re-skinned with all behavior hooks intact. No tokens.css or cursor references remain. All reduced-motion and responsive guards are in place. The correct architecture for the ink/paper rhythm exists — only the color values are wrong.
