## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Phase 5 bot → gallery.json | Discord message text becomes `caption`; untrusted input crosses into the site data file the bot commits. |
| gallery.json → wall `<img alt>` | Caption is rendered into the DOM as alt text on this phase's wall. |
| npm registry → build | Masonry.js + imagesLoaded are new third-party runtime deps pulled at install. |
| bot-named `file` → `/gallery/<file>` src | The site trusts the bot-guaranteed unique filename (D-02) as the image path. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering (XSS) | wall `<img alt>` fed by `caption` | mitigate | Alt is set via Astro `.astro` auto-escaping only — never `set:html` on caption/alt; verify grep shows no `set:html` in GalleryPage. Alt attribute (not innerHTML), so even a malicious caption cannot execute. |
| T-04-02 | Information Disclosure | missing/renamed `file` → 404 image | accept | A missing `file` degrades to the `--color-ink-raised` aspect-box placeholder + alt text (UI-SPEC Empty & Fallback); no data leak, no layout break. |
| T-04-SC | Tampering (supply chain) | masonry-layout / imagesloaded install | mitigate | Pin exact versions (`--save-exact`), run `npm audit`; no high-severity advisory permitted in the runtime tree before the plan passes (mirrors T-01-SC..T-02.1-SC). |
| T-04-03 | Tampering | bot-named `file` path traversal in src | accept | Trust boundary documented (D-02): the bot guarantees unique, safe filenames; the site only string-concatenates into `/gallery/<file>` as an `src` attribute (auto-escaped, no filesystem read on the static site). Path handling is a Phase 5 bot-side responsibility. |
