<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| gallery.json `caption` → lightbox DOM | Discord-authored caption is rendered into the lightbox caption node + img alt (untrusted input, this is the headline threat). |
| touch/pointer events → lightbox nav | User gestures drive index changes and close; no privilege crossing, but must not desync the trap. |
| View Transitions swap → gallery.ts | Navigating away must fully tear down Masonry + document listeners or they leak/duplicate. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-04 | Tampering (stored/DOM XSS) | lightbox caption + img alt fed by Discord `caption` | mitigate | Build the caption node and alt exclusively via `createElement` + `textContent` (cart.ts:573-591 idiom) — NEVER `innerHTML`/`set:html`; verify grep shows no `innerHTML`/`set:html` in gallery.ts. A malicious caption becomes inert text, cannot execute. This is the phase's headline security requirement. |
| T-04-05 | Denial of Service (resource) | neighbor-image preload on every nav | accept | Preload is bounded to index±1 (two images) per nav via `new Image()`; realistic photo counts (tens–low hundreds, D-11) make this negligible. No unbounded prefetch. |
| T-04-06 | Elevation / state leak | leaked Masonry instances + document listeners across swaps | mitigate | `astro:before-swap` teardown resets the inited flag first, calls `masonry.destroy()`, and document listeners are bound once behind a module flag re-querying the live overlay (motion/index.ts + chrome.ts idioms) — no duplicate handlers accumulate. |
| T-04-SC | Tampering (supply chain) | masonry-layout / imagesloaded runtime use | mitigate | Versions pinned + `npm audit` clean in Plan 01 (T-04-SC); this plan only consumes them. Re-run `npm audit` if the lockfile changed. |
</threat_model>
