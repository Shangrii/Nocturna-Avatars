<objective>
Close the second BLOCKER (gap #2, CR-02): `core/jinxxy_api.py::_retry_delay` passes a raw server-controlled header value straight into `time.sleep()` with no upper bound. `Retry-After` is a delta in seconds, but `X-RateLimit-Reset` is conventionally a unix-epoch timestamp — a 429 carrying that header computes a multi-decade sleep that permanently hangs the `asyncio.to_thread` call running the poll or `/tienda sync`, and because no exception is ever raised, the poll's `@_poll.error` restart path never fires. This directly threatens the "scheduled 6-12h poll" automatic-sync half of the phase goal (STORE-SYNC-01).

Purpose: Untrusted server input must never drive an unbounded sleep. A `_MAX_BACKOFF` cap plus epoch-vs-delta handling is a small, self-contained, well-testable fix isolated to the API client and its test file (parallel-safe with 09-07).
Output: A clamped `_retry_delay` and a test proving a large/epoch header value yields a bounded delay.
</objective>
