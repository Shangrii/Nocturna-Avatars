<objective>
Close the sole remaining Phase-9 blocker (09-VERIFICATION.md truth #5, status: failed): a
regression introduced by the 09-09 WR-03 fix. In `../nocturna-bot/cogs/jinxxy.py::_run_sync`
(L195-217) the unconditional durable-snapshot upsert loop (step 5, L199-210) executes BEFORE
the gated cross-repo commit (step 6, `github_publish.sync_store`, L214-217). If `sync_store`
raises `GitHubPublishError` after a genuine Jinxxy field change was detected, the snapshot is
already advanced past a `store.json` that was never written — the next cycle's
`three_way_merge` (core/store_sync.py:134-135) then reads `live_v == snap_v`, misclassifies the
un-committed change as "Jinxxy unchanged, staff edit wins," and permanently drops the update.

Purpose: A transient GitHub transport failure must cause a clean retry on the next cycle
(STORE-SYNC-01: "errors go to logs only"), not a silent, unrecoverable loss of a legitimate
price/name/category/nsfw/date update.

Output: `_run_sync` reordered so the gated commit runs BEFORE the unconditional snapshot upsert
loop (fix sketched in 09-REVIEW.md CR-01, second-pass), plus a regression test proving the
snapshot does not advance across a failed commit. This plan builds on the already-executed and
committed 09-09 state; it does not modify plans 09-01..09-10.
</objective>
