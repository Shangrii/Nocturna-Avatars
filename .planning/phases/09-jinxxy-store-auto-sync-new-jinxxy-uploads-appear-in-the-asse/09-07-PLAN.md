<objective>
Close the two merge/transport BLOCKERS behind the phase's headline promise — "staff hand-edits are never clobbered" (gap #1, WR-01 + WR-05). Today `core/github_publish.py::_sync_store_sync.build_tree` re-fetches the live `store.json` but then ignores it and writes a stale pre-computed products list, so a concurrent `/tienda medios` attach (which `JINXXY_DEPLOY.md` explicitly tells staff to run per product right after the first sync) is silently reverted. Separately, `core/store_sync.py::three_way_merge` with `current=None` (staff deleted a still-live product) has no explicit branch and appends an empty/partial `{}` entry into `products`.

Purpose: These are pure/near-pure defects with defined inputs and outputs, both directly contradicting STORE-SYNC-01 ("never overwrites staff-edited fields") and STORE-SYNC-02 ("the sync never overwrites them"). Fixing them in the two cores keeps the fix testable in isolation before the cog (09-09) is touched.
Output: A re-grafting `build_tree`, an explicit `current is None` merge branch, and new tests pinning both failure paths (none of the existing 313 tests exercise them).
</objective>
