<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| bot → Jinxxy API | outbound HTTPS with the secret `x-api-key`; responses are untrusted input |
| bot → logs | error/debug logging must never carry the key or full response bodies |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-03 | Information Disclosure | `x-api-key` in logs/errors | mitigate | Header-only, read at call time; `_http` interpolates only `exc.__class__.__name__`; `_require` logs only endpoint label + status — proven by a key-not-logged test |
| T-09-04 | Denial of Service (self-inflicted) | 429 / runaway retries | mitigate | Bounded backoff honoring `X-RateLimit-*`/`Retry-After`; sparse 6–12h cadence upstream |
| T-09-05 | Denial of Service (of content) | API error mistaken for empty storefront | mitigate | Any unrecoverable failure raises `JinxxyAPIError`; the function never returns `[]` on error, so the cog cannot mass-remove on an outage |
| T-09-06 | Cryptography / transport | TLS to the API | accept | HTTPS via `requests`; never hand-roll TLS (RESEARCH V6) |
</threat_model>
