<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| staff attachment → committed image | staff-uploaded image bytes are optimized and committed to the public site |
| non-staff → /tienda medios (+ autocomplete) | a command that commits to the site repo; must be staff-only, including its autocomplete |
| staff description text → store.json → site | free text written into a committed data file rendered on the site |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-18 | Elevation of Privilege | `/tienda medios` + its autocomplete by non-staff | mitigate | `_is_staff` gate FIRST on the command; the autocomplete returns `[]` for non-staff before any store read (CR-01 lesson) |
| T-09-19 | Tampering | malicious filename / raw user text in committed path | mitigate | Filenames are bot-generated numeric/slug + `.webp` (no raw user text); `optimize_to_webp` re-encodes bytes (strips EXIF/GPS, decompression-bomb guard intact) so arbitrary upload bytes never land verbatim |
| T-09-20 | Tampering (XSS) | staff description text on the site | mitigate | The site renders store.json fields through Astro auto-escaping only (T-06-01) — description is data end-to-end; the transport writes it verbatim without HTML |
| T-09-21 | Information Disclosure | leaked/committed API key | mitigate | `JINXXY_DEPLOY.md` mandates rotating the planning-pasted key and keeping it `.env`-only, never committed |
| T-09-SC | Tampering | pip installs | accept | No new packages (RESEARCH audit; reuses existing Pillow via image_optimize) |
</threat_model>
