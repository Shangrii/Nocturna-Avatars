<objective>
Close GAP-1 (UAT, 2026-07-11): staff have no Discord path to set a product's `editor` (credited creator), so crediting a creator required a forbidden hand-edit of `store.json`. Add a staff-gated `/tienda editar` command that writes only the `editor` field into the checkoutUrl-matched product via a new object-aware transport function, keeping `editor` a staff-owned field the Jinxxy sync never clobbers.

Purpose: `editor` is the one staff-owned metadata field the phase promised but never exposed on the Discord surface (`/tienda medios` covers `images`/`description` only). This finishes the "staff never edit JSON for a field the site expects" contract (STORE-SYNC-02), while locking the merge guarantee that a staff-set `editor` is preserved (STORE-SYNC-01, D-12/D-09).

Output: a `set_store_editor` transport function, a `/tienda editar` command with product autocomplete + input validation, and tests (transport contract, command staff-gate/validation, and a merge regression pinning that `editor` survives a sync).

Cross-repo, bot-side only. All code lives in `../nocturna-bot`; the website repo gets zero component changes (`store.json` is written at runtime by the bot; `StorePage.astro` already renders `editor`). Keep the bot suite green: `cd ../nocturna-bot && python -m pytest -q` (baseline 338/338).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Discord staff invoker → /tienda editar | Untrusted `editor` string crosses into a cross-repo git commit writing store.json |
| store.json (bot write) → GitHub Pages | Committed content is served publicly on the site |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-20 | Spoofing/Elevation | /tienda editar + editar autocomplete | mitigate | `_is_staff` gate runs FIRST (before defer/any work); autocomplete returns [] for non-staff — reuses the T-09-14/T-09-18 pattern |
| T-09-21 | Tampering/Injection | editor string → store.json JSON | mitigate | Validate before write: strip, reject empty/over-100/control-or-newline chars; JSON write goes through `_serialize_json` (json.dumps escapes quotes/control chars) so no structural break |
| T-09-22 | Tampering | editor string → git commit message | mitigate | Commit message is the fixed template `store: set editor for {checkout_url}` referencing the validated https key only; the raw `editor` text is NEVER interpolated into the message |
| T-09-23 | Information disclosure | error paths | mitigate | D-05: GitHubPublishError → log.exception only + a single ephemeral reply to the staff invoker; nothing posted to the public announce channel |
| T-09-24 | Denial of service | duplicate/no-op editor writes | mitigate | No-op guard: an unchanged editor returns committed=False and issues no commit/ref-patch, avoiding a needless Pages rebuild |
| T-09-SC | Tampering | npm/pip/cargo installs | accept | No new package installs — reuses discord.py + requests already pinned in requirements.txt; no legitimacy checkpoint needed |
</threat_model>
