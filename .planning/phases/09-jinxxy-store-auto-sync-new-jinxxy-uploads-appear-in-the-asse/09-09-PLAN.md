<objective>
Close the cog-side sync/poll orchestration defects — one BLOCKER (WR-03, gap #1) and four confirmed warnings (CR-01, WR-02, WR-04, WR-06) — all in `cogs/jinxxy.py`. WR-03: the snapshot is upserted only inside `if result["changed"]:`, so a no-change cycle where Jinxxy already matches a staff value leaves the snapshot stale, and a LATER staff edit on that field is misread as "both changed" and reverted by Jinxxy — violating the D-12 staff-protection contract. CR-01: `on_ready` and the poll's own immediate first tick both call `_run_sync` on boot → duplicate sync + double announce. WR-02: `_on_poll_error` restarts with zero cool-down → retry hammer. WR-04: a `/me` response missing `username` silently builds `jinxxy.com//slug` keys and mass-rewrites the store. WR-06: a staff-added product with an unusable/missing `checkoutUrl` is dropped from the repo on the next changed sync.

Purpose: These all defend the STORE-SYNC-01 promise ("never overwrites staff-edited fields", "never mass-removes"). Depends on 09-07 so the corrected merge/transport core is in place before the cog's snapshot/reconcile wiring is validated end-to-end.
Output: A hardened `_run_sync` / `on_ready` / `_on_poll_error`, plus tests pinning each fixed path.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Jinxxy API (/me, product details) → bot | A malformed-but-2xx response can drive a mass store rewrite |
| Jinxxy/GitHub outage → poll loop | A persistent failure can turn the 6-12h cadence into a tight retry loop |
| staff-edited store.json → sync | A stale snapshot or a dropped unkeyable entry silently loses staff work |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-09-09-01 | Tampering | stale snapshot reverting a later staff edit | mitigate | Upsert the snapshot on every successful sync (Task 1); a matching-but-unflagged live change still advances it |
| T-09-09-02 | Tampering / Info loss | unkeyable staff product silently deleted | mitigate | Carry unkeyable/duplicate current entries through verbatim (Task 1) |
