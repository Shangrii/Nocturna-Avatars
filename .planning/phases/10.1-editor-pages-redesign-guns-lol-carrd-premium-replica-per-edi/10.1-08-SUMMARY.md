## Decisions Made
- Robots directive emitted from `<head>` (BaseLayout prop) rather than a body-level `<meta>` in the directory component, because crawlers ignore robots meta found in `<body>`.
- Credit href is validated against `/^[a-z0-9-]+$/` before `setAttribute`, and the `/e/` prefix is a fixed literal — a crafted `editor` value cannot escape same-origin (T-10.1-08-03).
- `resolveSrc` uses `file.includes('/')` to distinguish a full path from a bare filename (a leading slash also contains a slash), satisfying the relayed 10.1-05 contract.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] noindex,follow moved to <head> via a BaseLayout prop**
- **Found during:** Task 1 (directory restyle)
- **Issue:** The plan suggested injecting `<meta name="robots">` from within the directory section on the assumption "Astro hoists head-level meta." It does not — the built meta landed in `<body>`, where Googlebot ignores it, so the D-16 / T-10.1-08-02 noindex requirement would not actually take effect.
- **Fix:** Added an optional `robots` prop to `BaseLayout` (rendered in `<head>`) and passed `noindex,follow` for the `editors` concept from the `[lang]/[page].astro` resolver — the plan's sanctioned alternative ("OR add it via the page"). Verified `robots` now precedes `</head>` in the built page and is absent from other concept pages (store checked).
- **Files modified:** src/layouts/BaseLayout.astro, src/pages/[lang]/[page].astro, src/components/sections/EditorsDirectory.astro
- **Verification:** `npm run build` exits 0; robots meta index < `</head>` index in dist/en/editors; store page has no robots meta.
- **Committed in:** `7bb147b` (Task 1 commit)
