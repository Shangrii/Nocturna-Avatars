# Phase 10.1 Plan 11: Background Media + Audio Upload Endpoints Summary

**Two cross-repo FastAPI endpoints (`POST /editor/media`, `POST /editor/audio`) that validate, per-kind size-cap, server-side optimize (WebP for raster, ffmpeg muted-MP4 transcode for GIF/video), and commit editor background media + audio under the session slug — failing closed when ffmpeg is unavailable.**

## Accomplishments
- `POST /editor/media`: classifies image / GIF / video by content-type AND extension, rejects SVG + any non-media before decode, enforces per-kind streamed caps (image 2 MB, GIF/video 10 MB, D-19) with an early abort, optimizes raster via `optimize_to_webp` and GIF/video via an ffmpeg muted-MP4 transcode (D-18/D-20), and commits only the re-encoded bytes under `ident['slug']`.
- ffmpeg transcode runs off the event loop on a temp file and **fails closed** — a missing/erroring ffmpeg returns the media-error copy and commits nothing (never an un-optimized file, T-10.1-11-03).
- `POST /editor/audio`: audio allowlist (MP3/OGG/M4A/WEBM/WAV) by content-type AND extension, 5 MB streamed cap (D-19), commits as-is under the session slug — the path the plan-10 theme panel writes into `page.theme.audio` (D-06).
- Both paths are built from the SESSION slug only (never a client-supplied path segment, T-10.1-11-02 / 10-D-08) with a server-generated uuid filename.
- 12 new endpoint tests (happy path, type reject, over-cap-before-optimize, ffmpeg fail-closed, session-slug path) for both endpoints.

## Decisions Made
- GIF and video share the 10 MB cap and both transcode to a muted H.264 MP4 (a GIF background is a short muted loop — D-18/D-20).
- ffmpeg fails closed rather than committing an un-optimized file when the binary is absent or errors.
- Audio commits as-is within the 5 MB cap (transcode/normalize not required for correctness; deferred as optional).
