# Phase 10.1: Editor Pages Redesign — guns.lol/carrd premium replica - Context

**Gathered:** 2026-07-15
**Status:** Ready for planning

<domain>
## Phase Boundary

Redesign the per-editor profile pages shipped in Phase 10 into a **premium guns.lol/carrd-style link-in-bio experience**: per-editor theming (background image/GIF/video, curated fonts, free colors, effects, audio), a **fully standalone visual identity** separate from the main site, a short `/e/<slug>` canonical URL, and no navbar link. Includes the matching theme-editing surface in the Phase 10 admin app (side-by-side live preview) and a tiny view-counter endpoint on the bot host.

This phase changes the LOOK, THEMING, and URL/discovery model of editor pages. It does not change who can edit (Discord OAuth, own-page-only), how publishing works (commit to repo, publish-on-save), or the block-content model (blocks still render, now inside the new shell).

</domain>

<decisions>
## Implementation Decisions

### Theming model
- **D-01:** **Granular per-editor knobs** (guns.lol model) — each editor independently sets background media, colors, font, button style, and effects. Not preset-only.
- **D-02:** Colors are **free hex pickers** PLUS a set of pre-designed professional palette options to start from. The main site's red/navy brand palette is NOT binding on editor pages.
- **D-03:** **~10–15 curated fonts** covering distinct vibes (clean sans, serif, display, gothic/blackletter, handwritten, pixel/retro, techno). Only the editor's chosen font loads on their page.
- **D-04:** **Full premium effects suite**, all opt-in per editor: glassmorphism cards, avatar glow/ring, link-button hover animations, animated username gradients, typewriter tagline, tilt-on-hover, particle/snow overlays, background overlay controls. User's words: "Everything, the whole premium feeling, I want high-end customizations."
- **D-05:** **Live Discord presence** on the page (status dot, optionally current activity) fetched client-side via Lanyard (public instance or self-hosted on the bot host — technical choice at research/planning time).
- **D-06:** **Background audio supported** — editor-uploaded music track with volume control, unlocked by the click-to-enter splash.
- **D-07:** **Curated specialty badges** (e.g. Outfits, Texturas, Blender, Dances) — badge set defined by the team; each editor picks theirs via the admin app. No free-form badge text.
- **D-08:** **View counter yes, custom cursors no.** Per-page view counts; no per-editor cursor styling (cursors were already removed site-wide in the redesign).
- **D-09:** Editors add **their own social links (TikTok, YouTube, anything) rendered with recognizable platform icons** — guns.lol-style icon row. Platform icon auto-detected from URL; fallback generic icon for unknown domains.

### Page layout
- **D-10:** **Link-in-bio shell + blocks**: fixed guns.lol-style header (avatar with glow, name, badges, presence, tagline, social icon row) in a centered glass card; the editor's Phase 10 blocks render below inside the same themed column. The block system survives.
- **D-11:** **Link buttons: style variants + accent** — editor picks button style (filled / outline / glass) and corner shape (sharp / rounded / pill); accent color and hover animation come from their theme. No per-button individual overrides.
- **D-12:** **Portfolio block renders as a compact 2–3 column thumbnail grid** inside the themed column; tapping opens a lightbox. Auto-pull behavior (credited store/gallery work, SFW-only) unchanged from Phase 10.
- **D-13:** **Single-language pages** — each editor writes their page in ONE language of their choice (schema keeps a `lang` field per editor rather than es/en duplicated content). One canonical URL per editor.

### URLs, separation & discovery
- **D-14:** Canonical URL is **`/e/<slug>`** (guns.lol-style vanity path). The old `/es/editores/<slug>` and `/en/editors/<slug>` routes redirect to it (static-host-compatible redirect, e.g. meta-refresh/canonical stub pages — mechanism is a planning call).
- **D-15:** Editor pages are **fully standalone**: no site navbar, no footer, no film grain, no site fonts — the editor's theme is 100% of the identity. Only a tiny discreet "nocturna" watermark link in a corner.
- **D-16:** The **/editores (/editors) directory page stays live but unlisted** — removed from the navbar, restyled to match/tease the new look, reachable via direct link/footer/mentions.
- **D-17:** **Editor credits on store cards AND gallery items link to `/e/<slug>`** — organic discovery without a navbar entry.

### Background media
- **D-18:** Backgrounds support **image + GIF + video** (mp4/webm looping muted). The admin app compresses/optimizes on upload.
- **D-19:** **Moderate size caps**: background video/GIF ≤ ~10 MB after compression, audio ≤ ~5 MB, images ≤ ~2 MB. All media commits to the website repo (GitHub Pages ~1 GB budget awareness).
- **D-20:** **Same experience on all devices** — muted looping video autoplays on mobile too; the splash screen gates the heavy load. No forced static fallback.
- **D-21:** **Full background treatment knobs**: overlay darkness (0–100%), optional blur, optional tint using theme colors — editor-controlled for legibility.

### Splash screen
- **D-22:** **Every editor page opens with a minimal themed splash** (blurred background peek + editor name + "click to enter" in their font). Consistent premium ritual; reliably unlocks audio and video autoplay.

### Admin app theming surface
- **D-23:** Theme editor is **side-by-side live preview**: grouped control panel (Background / Colors / Typography / Buttons / Effects / Audio) with an instant live page preview beside it — extends Phase 10's D-14 live-preview decision to theming.
- **D-24:** **~6–8 full theme presets** (complete palette + font + button style + effects combos, e.g. "Neon night", "Soft pastel", "Gothic", "Y2K") applied in one click, then any knob tweakable. These subsume the palette presets from D-02.

### View counter
- **D-25:** View counts served by a **tiny counter endpoint on the cinema/bot host** (same infra as the admin app, no third party). Page pings it client-side; graceful degradation (hide count) if the endpoint is unreachable.

### Rollout
- **D-26:** **Clean cutover** — new theme schema with sensible defaults so existing pages instantly render in the new shell with a default theme; old bilingual routes redirect to `/e/<slug>`; the admin theme editor ships in the same phase.

### Claude's Discretion
- Exact curated font list (which 10–15 fonts, hosting strategy — self-host preferred for perf) and the exact 6–8 theme preset designs.
- Implementation details of each effect (CSS/JS technique, performance budget per effect, reduced-motion handling).
- Media compression pipeline specifics (client-side vs server-side on cinema, formats, poster-frame extraction).
- Lanyard: public instance vs self-hosted; behavior when an editor isn't in the Lanyard guild.
- Platform-icon set/library for social links and the URL→platform detection map.
- Redirect mechanism for old routes on a static host; sitemap/SEO handling (index or noindex editor pages).
- View-counter endpoint shape (framework, storage, rate limiting/dedup).
- editors.json theme-schema shape and default theme values.

</decisions>
