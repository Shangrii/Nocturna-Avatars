# Phase 10.1 Plan 03: Editor Header Shell Components Summary

**The four guns.lol header-shell transform components — LinkButton (attribute-driven style×shape matrix), SpecialtyBadges (curated allowlist), SocialIconRow (URL→self-hosted-glyph with generic fallback), and the EditorHeaderCard glass composition with a named presence slot — all theme-token-driven, auto-escaped, and served by a self-hosted Simple Icons + Lucide SVG subset (no CDN).**

- **Completed:** 2026-07-16T02:05:00Z
- **Tasks:** 3
- **Files created:** 20 (4 components + 16 SVG icons)

## Accomplishments

- **LinkButton** emits `[data-btn-style]`/`[data-btn-shape]` (enum-whitelisted, defaulting to the wave-1 token values) so `editor-theme.css`'s `.editor-btn[data-btn-*]` matrix resolves the filled/outline/glass × sharp/rounded/pill combination — one page-level style, no per-button overrides (D-11). Safe outbound rel, escaped label, 44px target.
- **SpecialtyBadges** filters incoming keys to the exact bot-side `SPECIALTY_BADGES` allowlist (Outfits/Accessories/Dances/Textures/Blender/Modeling3D), drops unknown + duplicate keys, and renders theme-token pills; empty list → renders nothing (D-07).
- **SocialIconRow** defensively parses each URL, matches the hostname suffix against a registered-domain→platform map, and inlines the matching self-hosted glyph — unknown hosts fall back to the Lucide `globe`; malformed/relative URLs are skipped (D-09). Safe rels, theme-token colour, 44px targets.
- **EditorHeaderCard** composes avatar(+`glow`)/name(+`gradient`)/SpecialtyBadges/`presence` named slot/tagline(+`typewriter` hook)/SocialIconRow inside a `.editor-glass` card; each premium effect is opt-in per the editor's `effects[]` keys (matching `editors_model.KNOWN_EFFECTS`), all editor text auto-escaped (D-10).
- Self-hosted a 16-file SVG subset (10 Simple Icons social + 6 Lucide UI) under `src/icons/` — no icon-font, no CDN, no npm dep (T-10.1-03-SC).
- Validated the full composition through a throwaway probe page (built + asserted rendered output: attribute emission, XSS escaping of a `<b>&amp;` name, effect-gated classes, globe fallback for an unknown host, badge dedup/drop, zero brand-red leakage), then removed it — clean build back at 18 pages.

## Decisions Made

- **LinkButton props extended to `{label, url, btnStyle?, btnShape?}`** — the plan's literal signature was `{label, url}`, but the wave-1 cross-plan contract requires the shell to emit `[data-btn-style]`/`[data-btn-shape]`. The optional props default to the token values (`glass`/`rounded`) and are enum-whitelisted; the route (plan 07) passes the same page-level pair to every button, preserving "no per-button overrides" (D-11).
- **Icons fetched-then-committed** (Simple Icons v13 + Lucide static via jsDelivr), mirroring plan 02's font approach — no render-time third-party fetch. Simple Icons normalized to `fill="currentColor"`; `<title>` stripped (the anchor carries the aria-label).
- **`twitter.svg` omitted** (simple-icons deprecated it); `twitter.com` maps to the `x` glyph, so no gap.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] LinkButton needs btnStyle/btnShape inputs to satisfy the attribute-driven contract**
- **Found during:** Task 1 (LinkButton)
- **Issue:** The plan's `{label, url}` prop signature gives the button no way to know which style×shape enum to mirror onto its data-attributes, yet the wave-1 contract in `editor-theme.css` requires `[data-btn-style]`/`[data-btn-shape]` for the matrix CSS to resolve.
- **Fix:** Added optional `btnStyle`/`btnShape` props defaulting to the Midnight-Nocturna token values, enum-whitelisted before emission. All buttons on a page receive the same page-level pair from the route (no per-button override, D-11 preserved).
- **Files modified:** src/components/editor-shell/LinkButton.astro
- **Verification:** Probe page rendered `data-btn-style="outline" data-btn-shape="pill"` from passed props; defaults resolve to `glass`/`rounded` when omitted.
- **Committed in:** `43126b7` (Task 1 commit)
