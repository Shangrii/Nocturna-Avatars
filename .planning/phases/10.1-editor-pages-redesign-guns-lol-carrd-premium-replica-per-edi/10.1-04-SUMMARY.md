# Phase 10.1 Plan 04: Live Editor-Shell Components Summary

**Three net-new client-dynamic components — Lanyard presence dot, cinema view-counter ping, and splash-gated background audio — all reveal-on-success / hide-silently, writing third-party data via textContent only.**

## Performance

- **Duration:** ~6 min
- **Started:** 2026-07-15T19:57:00Z
- **Completed:** 2026-07-15T20:01:30Z
- **Tasks:** 2
- **Files modified:** 6 created

## Accomplishments
- `PresenceDot` fetches the public Lanyard instance client-side, maps `discord_status` to a fixed semantic dot colour (online/idle/dnd/offline) with an accent ring, optionally shows the activity name via textContent, and stays hidden with no error text on any failure (D-05).
- `ViewCounter` listens for the `editor:enter` splash event, pings `https://editors.nocturna-avatars.site/api/views/<slug>?hit=1` exactly once, writes the count via textContent only, and hides on any non-200/network/malformed response (D-25 / D-08).
- `AudioPlayer` renders nothing without a src; the `<audio>` starts muted+loop+preload="none" and only unmutes/plays after the `editor:enter` gesture (autoplay unlock, D-22), with a 44px volume/mute toggle + slider that also work on mobile (D-06/D-20); a blocked `play()` leaves the control muted with no error text.

## Decisions Made
- Inlined all glyphs (Lanyard dot is CSS, view = eye SVG, audio = volume-on/volume-off SVG) directly in each component following the `LightboxOverlay.astro` inline-SVG pattern, rather than creating `src/icons/ui/*` files — the plan permitted either and inlining avoids a shared-asset dependency on plan 03.
- Used the exact `https://editors.nocturna-avatars.site/api/views` base as a single contiguous constant so it matches the plan-12 endpoint contract verbatim.
- One shared `play()` code path serves both the `editor:enter` unlock and the manual toggle, so autoplay-block handling (fallback to muted) is defined once.
