# Phase 10.1 Plan 05: Editor Blocks Theme-Token Swap + Portfolio Grid Summary

Refactored the seven Phase-10 block components + BlockRenderer from brand tokens to `--theme-*` tokens (a token-swap, not a rewrite) and upgraded PortfolioBlock to a compact 2-3 column thumbnail grid whose cells open the shared gallery lightbox — while keeping the build-time SFW-only credited auto-pull and the D-02 no-`set:html` invariant byte-for-byte intact.

## What Was Built

**Task 1 — Token swap (commit c0f5aa9):** Every brand color/font reference in the `<style>` blocks of BioBlock, HeadingBlock, TextBlock, QuoteBlock, LinksBlock, and BlockRenderer now reads a `--theme-*` token: `--color-red`/`--color-red-on-ink`→`--theme-accent`, `--color-white`→`--theme-text`, `--color-white-dim`→`--theme-text-muted`, `--color-ink-raised`→`--theme-surface`, `--font-*`→`--theme-font`. LinksBlock's border and hover fill (previously `--color-border`/`--color-red-soft`) were recolored with `color-mix()` over the theme text/accent tokens. `--space-*`, `--touch-min`, and the `--type-*`/`--lh-*` typography primitives were left as-is. Markup, defensive reads, prop shapes, `rel="noopener noreferrer nofollow"`, and reduced-motion guards are unchanged.

**Task 2 — PortfolioBlock (commit 199acde):** The grid went from `1fr → repeat(2,1fr)@480px` to a compact `1 → 2 col (480px) → 3 col (640px)` thumbnail grid with `max-width: 560px; margin-inline: auto` breakout. Each cell frame is now a `<button type="button" data-gallery-tile data-file={item.image} data-caption={item.caption} data-index={i}>` wrapping the existing `<img>` (badge + figcaption retained), so `gallery.ts::initLightbox` binds click and native Enter/Space with zero new JS. Frame/badge/caption were recolored to `--theme-surface`/`--theme-accent`/`--theme-text`/`--theme-text-muted`; button chrome is reset to inherit. The entire build-time credited auto-pull (store + gallery SFW-only join by exact slug, NSFW fully excluded, extra items, defensive reads) is preserved verbatim; empty list still renders NOTHING.

## Deviations from Plan

### Auto-fixed / scope-consistent adjustments

**1. [Rule 2 - Missing critical functionality] Recolored un-mapped brand tokens**
- **Found during:** Task 1
- **Issue:** LinksBlock referenced `--color-border` and `--color-red-soft`, and PortfolioBlock referenced `--color-border` — brand tokens not defined in `editor-theme.css`, so they would render undefined on standalone editor pages. `--color-red-soft` is also caught by the Task 1 acceptance grep (`var(--color-red`).
- **Fix:** Recolored to `color-mix(in srgb, var(--theme-text) 14%, transparent)` (borders) and `color-mix(in srgb, var(--theme-accent) 14%, transparent)` (soft hover fill), matching the border/tint convention in `editor-theme.css`. Satisfies the D-10 `<done>` criterion "read theme tokens only."
- **Files modified:** LinksBlock.astro, PortfolioBlock.astro
- **Commits:** c0f5aa9, 199acde

**2. [Rule 2 - a11y/motion discipline] Portfolio button focus + reduced-motion**
- **Found during:** Task 2
- **Issue:** Converting the frame `<div>` to a `<button>` added a hover transform; project-wide reduced-motion discipline (UI-SPEC Effects Catalog) requires a guard, and keyboard focus needs a visible ring.
- **Fix:** Added `:focus-visible` outline (`--theme-accent`) and a `@media (prefers-reduced-motion: reduce)` block disabling the transition/transform.
- **Files modified:** PortfolioBlock.astro
- **Commit:** 199acde

**3. ImageBlock not modified**
- ImageBlock.astro was listed in `files_modified` but its `<style>` carried no brand color/font tokens (only `border-radius`). The swap was a no-op, so the file was left unchanged.

## Known Stubs / Cross-Plan Dependencies

- **`data-file` full-path vs gallery.ts prefix (plan 08, same wave):** PortfolioBlock emits `data-file={item.image}` as a full src (e.g. `/gallery/foo.webp`, store paths, extra paths) per this plan's `<interfaces>` contract ("data-file=<img src>"). The current `gallery.ts` renders `/gallery/${entry.file}` (bare filename). Plan 08 owns `gallery.ts`/`LightboxOverlay.astro` and must accept a full-path `data-file` for the editor portfolio lightbox. This block emits the documented hooks; wiring correctness depends on plan 08's initLightbox handling. Not modified here (scope guard).
- **`--type-*` / `--lh-*` typography primitives:** blocks reference `--type-body`, `--lh-body`, `--type-heading`, `--type-card-title`, `--type-label`, `--lh-label` etc. These are NOT in the enumerated swap mapping and are NOT declared in `editor-theme.css` (only `--space-*`/`--touch-min` carry over). Left as-is per plan scope. If editor pages do not otherwise receive these primitives, the layout plan (06) should emit them or they will fall back to browser defaults. Flagged for the layout/theme owner — outside this plan's explicit mapping.
