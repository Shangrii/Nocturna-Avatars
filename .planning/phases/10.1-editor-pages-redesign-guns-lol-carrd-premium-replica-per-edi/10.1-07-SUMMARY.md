## Decisions Made
- **Opaque page bg layer over the layout fallback:** `EditorLayout` already renders a `.editor-bg` fallback layer, but CSS backgrounds cannot play video. The page renders its own bg-media layer (with an opaque `--theme-bg` base) that paints over the layout layer, so video is supported and there is exactly one darken scrim rather than two stacked scrims.
- **Lightbox on a chrome-free page:** The chrome-free `EditorLayout` loads no brand stylesheet, so the shared lightbox (`.dc-overlay` from chrome.css + `.lightbox*` from gallery.css) would be unstyled. Imported `gallery.css`, re-declared the small `.dc-overlay` backdrop inline, and aliased the handful of brand tokens the lightbox uses (`--color-white`, `--color-red`, `--font-mono`, …) onto the editor's `--theme-*` tokens so the lightbox adopts the page theme.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] CSS comment lexer errors surfaced on first EditorLayout consumption**
- **Found during:** Task 1 (build)
- **Issue:** This is the first page to mount `EditorLayout`, so `editor-theme.css`/`editor-fonts.css` entered the build graph for the first time. Two dormant comment bugs broke the CSS toolchain: (a) unbalanced apostrophes (`browser's`, `don't`, `editor's`) made Tailwind v4's lexer throw "Unterminated string"; (b) the sequence `--type-*/--lh-*` inside a comment contains `*/`, which prematurely closed the CSS comment and left `--lh-*` as stray CSS → lightningcss "Unexpected token Delim('*')".
- **Fix:** Comment-only edits — removed the three apostrophes and added a space (`--type-* / --lh-*`) so `*/` no longer appears mid-comment. Zero CSS behavior change.
- **Files modified:** src/styles/editor-theme.css, src/styles/editor-fonts.css
- **Verification:** `npm run build` progressed past Tailwind and lightningcss and exited 0; `/e/aria-test` emitted.
- **Committed in:** `547ccb8` (Task 1 commit)

**2. [Rule 2 - Missing Critical] Restored lightbox styling for the chrome-free page**
- **Found during:** Task 1 (assembly)
- **Issue:** The plan requires portfolio cells to open the shared lightbox, but `EditorLayout` imports no brand CSS, so the lightbox overlay would render unstyled/broken (its `.dc-overlay`/`.lightbox*` rules + brand tokens live in chrome.css/gallery.css).
- **Fix:** Imported `gallery.css`, inlined the minimal `.dc-overlay` backdrop rules, and mapped the brand tokens the lightbox references onto the editor `--theme-*` tokens.
- **Files modified:** src/pages/e/[slug].astro
- **Verification:** Build exits 0; `LightboxOverlay` present and `gallery.ts` imported; lightbox derives entries from the rendered portfolio tiles.
- **Committed in:** `547ccb8` (Task 1 commit)
