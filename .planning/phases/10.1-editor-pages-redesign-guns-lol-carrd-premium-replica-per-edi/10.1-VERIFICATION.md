### Gaps Summary

Of the 26 locked decisions, 25 are cleanly verified in the codebase with no caveats beyond expected human/live-deploy testing. One genuine, code-verifiable regression was found: `src/components/sections/EditorsDirectory.astro` (touched in both Plan 01 and Plan 08) never migrated its `tagline` read off the pre-Phase-10.1 bilingual `{es,en}` object shape, even though `editors.json`'s `tagline` field became a plain string in this same phase (D-13). This was explicitly flagged as a known, deferred issue in `10.1-01-SUMMARY.md` ("expected and in-scope for later plans... the directory is restyled later") but Plan 08 restyled the directory without closing this specific gap. The result, confirmed by inspecting the actual build output (`dist/es/editores/index.html`), is that the directory's tagline line never renders for any editor, even one with a non-empty tagline. The avatar, name, and canonical `/e/<slug>` link (the D-17 discovery path) all render and link correctly — only the tagline text is silently dropped. This is a small, well-scoped fix (update one interface + one field-read in one file) and does not affect the phase's core deliverable (the standalone `/e/<slug>` pages, theming system, redirects, or cross-links), but it is a real defect introduced by this phase's own schema migration and should be closed before considering the phase fully done.

The BLOCKER and two WARNINGs raised in `10.1-REVIEW.md` (CR-01 stored-XSS via unguarded href schemes, WR-01 CSS-token injection, WR-02 multi-portfolio lightbox indexing) were independently re-verified against their fix commits (`1582790`, `b39e00a`, `aa3d98f`) by reading the actual diffs — all three fixes are logically correct and properly wired into every affected consumer (LinksBlock, LinkButton, SocialIconRow, the route filter, EditorLayout's color emission, and gallery.ts's lightbox index derivation).
