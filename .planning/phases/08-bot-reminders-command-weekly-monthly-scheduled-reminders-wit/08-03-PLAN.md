<objective>
Wire the reminders cog to life: the `RemindersCog` GroupCog (`/recordatorio`), the staff-gated
`crear` subcommand (validated slash params + multi-line `MensajeModal`), the delivery helper
(mention line + branded embed + `AllowedMentions` suppression + seeded reactions), the repo's
FIRST background scheduler (`@tasks.loop(minutes=1)` with catch-up classification and the
D-16 lifecycle), and the `bot.py` extension load + `REMINDERS_TZ` fail-fast.

Purpose: After this plan, a staff member can create a reminder and the bot fires it on
schedule, survives restarts (next_fire_utc cursor in SQLite), and catches up recent misses
marked "⏰ atrasado". Management commands (listar/borrar/editar) land in 08-04.
Output: A functioning create-and-fire pipeline, unit-tested.

**Locked design choice (RESEARCH Open Q1 / A3):** advance-after-send crash semantics — the
scheduler sends first, then advances `next_fire_utc`. A crash between the two can cause a
rare missed advance (healed by the next tick's dedupe-by-recompute) rather than a double
ping; the D-13 grace window covers misses. Document this in a code comment.

repo. Commit in `nocturna-bot`. Deployment to cinema (git pull + systemd restart + real .env)
is a manual user step, out of phase scope — acceptance here is unit tests + import checks.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Discord interaction → cog | any guild member can invoke /recordatorio subcommands; only staff may act |
| staff message body → public channel send | custom text (typos incl. @everyone) crosses into a public ping-capable send |
| SQLite rows → scheduler | persisted rows drive automated sends every minute |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Elevation of Privilege | crear (and all subcommands) | mitigate | `_is_staff` role-intersection gate as the first statement; non-staff get ephemeral "Sin permisos."; bots/role-less never staff (D-02) |
| T-08-02 | Denial of Service / Tampering | _deliver mass-ping | mitigate | `discord.AllowedMentions(everyone=False, roles=True, users=True)` on every send — API-level suppression regardless of message text (D-11); mentions line built only from the typed `discord.Role` param |
| T-08-04 | Tampering | crear input validation | mitigate | parse_time/parse_date/valid_weekday/valid_day_of_month reject malformed schedule input before persistence; past one-off dates rejected |
| T-08-05 | Denial of Service | scheduler loop | mitigate | Per-reminder try/except + @loop.error restart — one bad row (deleted channel, bad emoji, Forbidden) can never stop all reminders (Pitfall 1) |
| T-08-06 | Denial of Service | catch-up | mitigate | classify_fire grace window: no stale-reminder dump after long outages; recent misses fire once marked atrasado (D-13) |
| T-08-07 | Denial of Service | seeded reactions | mitigate | parse_emojis cap (6) + per-emoji HTTPException skip (Discord max 20/msg) |
| T-08-08 | Tampering | sends to unintended channels | accept | Staff trust boundary: the channel is staff-chosen via the typed picker; bot needs Send Messages perms; Forbidden/NotFound handled gracefully (log + skip) |
| T-08-09 | Information Disclosure | reminder message content | accept | Content is staff-authored for team channels; no secrets/PII expected; renders as embed text (never executed) |
</threat_model>
