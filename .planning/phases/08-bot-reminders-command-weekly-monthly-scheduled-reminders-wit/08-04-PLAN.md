<objective>
Complete the `/recordatorio` command surface with the management subcommands: `listar`
(readable Spanish overview), `borrar` (autocomplete-picked deletion), and the full `editar`
(autocomplete pick → optional schedule/channel/name/mention/reactions params → message modal
pre-filled with the stored body). Autocomplete is the repo's FIRST use of
`@app_commands.autocomplete` — suggestions are `"{name} — {schedule summary}"` labels backed
by the reminder id, so staff never memorize IDs (D-04/D-05).

Purpose: Staff can inspect, remove, and fully modify reminders without delete+recreate
(D-15 was explicitly chosen over delete+recreate).
Output: The complete D-01 subcommand set, unit-tested; phase feature-complete.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Discord interaction → cog | any guild member can invoke listar/borrar/editar and trigger autocomplete |
| autocomplete value → DB lookup | the submitted `recordatorio` string is attacker-choosable (not limited to suggested choices) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Elevation of Privilege | listar/borrar/editar | mitigate | `_is_staff` gate as the first statement of every subcommand; autocomplete leaks nothing actionable (suggestions are names staff already see) |
| T-08-10 | Tampering | borrar/editar id param | mitigate | The autocomplete VALUE is user-controlled free text — parse with int() in try/except + db.get_reminder existence check; parameterized `?` lookups (no SQL injection); malformed → ❌ ephemeral |
| T-08-04 | Tampering | editar merged-schedule validation | mitigate | Same validators as crear re-run on the MERGED row so a partial edit can never persist an inconsistent schedule (e.g. monthly without day) |
| T-08-11 | Information Disclosure | autocomplete callback | accept | Reminder names/schedules are staff-facing team data with no secrets; Discord only shows suggestions to the invoking user, and every mutating path is staff-gated |
</threat_model>
