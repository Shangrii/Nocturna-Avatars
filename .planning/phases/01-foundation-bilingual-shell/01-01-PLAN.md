<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| developer → npm registry | Astro + its dependency tree are pulled from npm during install/build |
| GitHub Actions runner → GitHub Pages | The deploy workflow has a token that can publish site content and could touch the custom domain |
| visitor browser → static site | Only untrusted input is `navigator.language` / stored language pref used to choose a redirect target |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-SC | Tampering | npm install (Astro + deps) | mitigate | Pin exact Astro version in package.json (no `^`/`~`); commit package-lock.json so CI installs the locked tree; legitimacy gate (Task in plan if [ASSUMED] packages added). Astro is a first-party, widely-used framework → low supply-chain risk but still pinned. |
| T-01-01 | Elevation of Privilege | GitHub Actions deploy workflow | mitigate | Least-privilege `permissions` block: `contents: read`, `pages: write`, `id-token: write` only. No long-lived PAT; uses the workflow's `GITHUB_TOKEN` via `actions/deploy-pages`. No secrets echoed to logs. |
| T-01-02 | Tampering | CNAME / custom domain on cutover | mitigate | `public/CNAME` (`nocturna-avatars.site`) is emitted to `dist/` so every deploy reasserts the domain; human checkpoint verifies the domain survived the Pages source cutover (D-09, PLAT-02). |
| T-01-03 | Tampering / Open redirect | root `/` language-detection redirect | mitigate | Redirect targets are hard-coded to the two literal paths `/es/` and `/en/` only; `navigator.language` is used solely to choose between them, never interpolated into the URL — no open-redirect surface. |
| T-01-04 | Information Disclosure | GitHub Actions secrets in client output | accept | This phase has no secrets in client code (no API keys, no backend). Static output contains only public marketing content. No mitigation needed beyond not introducing env-var injection into pages. |
</threat_model>
