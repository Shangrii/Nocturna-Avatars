<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| visitor browser → localStorage | The language preference (`nocturna-lang`) is read back by the root redirect; a tampered value could choose a redirect target |
| visitor → outbound Discord/Instagram links | External navigation to third-party domains |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-05 | Tampering | localStorage `nocturna-lang` consumed by root redirect | mitigate | The root redirect (plan 01) must treat the stored value as untrusted: accept only the literal allow-list `'es'`/`'en'`, else fall through to `navigator.language`/default. The switcher only ever writes those two literals. No URL is built from the raw stored value. |
| T-01-06 | Information Disclosure | external links (Discord invite, Instagram) | mitigate | All `target="_blank"` external links carry `rel="noopener"` (and noreferrer) to prevent reverse-tabnabbing window.opener access. |
| T-01-07 | Tampering (DOM/XSS) | modal/nav copy injected from dictionaries | accept | Dictionary strings are author-controlled static JSON rendered through Astro's auto-escaping template interpolation (not `set:html`), so no untrusted HTML is injected. Modal title uses emphasis via a dedicated key/markup, not raw HTML from data. |
| T-01-SC | Tampering | npm dependencies (this plan adds none) | mitigate | No new packages introduced; chrome.ts is dependency-free vanilla TS. Locked tree from plan 01 governs. |
</threat_model>
