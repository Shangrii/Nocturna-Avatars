<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| dictionary JSON → rendered HTML | Author-controlled copy (packages, about, empty-state) is interpolated into pages |
| visitor → in-page Discord CTA | Every shell/empty-state exposes a `.dc-trigger` opening the shared modal (external nav) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-08 | Tampering (XSS) | package/about/empty-state copy rendered from JSON dictionaries | mitigate | All dictionary strings render through Astro's auto-escaping `{...}` interpolation (no `set:html`). If any copy needs emphasis markup, use static Astro template elements, never raw HTML from the data file. No untrusted/user-supplied content exists this phase (static authored JSON). |
| T-01-09 | Information Disclosure | in-page external Discord/social links | mitigate | All `target="_blank"` links carry `rel="noopener"`; consistent with the chrome from plan 02. |
| T-01-10 | Denial of Service / broken UX | shell pages with no real data (galeria/catalog) | mitigate | Shells render branded EmptyState components with a reachable CTA — pages never render blank or error, preserving the conversion path (NAV-03) even without data. |
| T-01-SC | Tampering | npm dependencies (this plan adds none) | mitigate | No new packages; pure Astro components. Locked tree from plan 01 governs. |
</threat_model>
