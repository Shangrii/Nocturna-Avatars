<reference_patterns>
Verified from 05-RESEARCH.md — use directly.

🌙 removal / dismiss (BOT-05, D-06/D-07/D-08/D-09):
- in `on_raw_reaction_add` (built in 05-03), add a branch for `str(payload.emoji) == "🌙"` using the SAME staff role gate as ✅ (D-08)
- `_unpublish(message)`: if the message is published (has the bot's 🟢 marker and/or gallery.json holds `*-{msgID}-*` entries), call `github_publish.remove_message(message.id)` (removes photos + entries in one commit, D-07), then remove the 🟢 marker and send a Spanish-first auto-delete reply "Removed N photos…" (D-09) — returning the message to pending so a later ✅ republishes it
- if the message is pending (never published — no 🟢, no entries), dismiss it: remove the bot's ✅ prompt so it won't be published, and do NOT commit anything (D-07)

Auto-unpublish on delete (D-10):
- `@commands.Cog.listener() async def on_raw_message_delete(payload)`: return unless `payload.channel_id == config.PHOTO_CHANNEL_ID`; derive the message id from `payload.message_id`; call `github_publish.remove_message(payload.message_id)` (no-op if it had no published entries — safe for non-photo deletes). Channel is the source of truth (accepted risk: accidental delete removes photos).

Persistent error surfacing (D-19):
- wrap the publish/remove commit calls; when github_publish exhausts its retries and raises (D-18), post a NON-auto-deleting reply describing the failure + add a ⚠️ reaction so it doubles as a retry to-do; staff retry by removing + re-adding ✅. Do NOT swallow the error silently.

Startup backfill (D-20, Pattern 4):
- `core/db.py`: add `get_cursor()` (SELECT last_processed_message_id FROM gallery_state WHERE id=1) and `set_cursor(mid)` (INSERT OR REPLACE), following the existing sqlite idiom
- in an `on_ready`/cog-load hook: `after = discord.Object(id=get_cursor()) if get_cursor() else None`; `async for msg in channel.history(after=after, limit=None, oldest_first=True): await self._reconcile(msg); set_cursor(msg.id)`
- `_reconcile(msg)`: add the ✅ prompt if a staff image post lacks it; if a staff ✅ is present but the message isn't published (no 🟢 / no entries) -> publish; if a staff 🌙 is present -> unpublish/dismiss. Published-state is DERIVABLE from the 🟢 marker + `*-{msgID}-*` entries (no per-message DB, D-14).

Removal derivation (D-14): a message's files/entries are exactly those whose `file` matches the EXACT `{msgID}` middle segment of `{YYYYMMDD}-{message.id}-{index}.webp` (split on `-`; do not substring-match). This lives in `github_publish.remove_message` (05-02); the cog only supplies `message.id`.
</reference_patterns>
