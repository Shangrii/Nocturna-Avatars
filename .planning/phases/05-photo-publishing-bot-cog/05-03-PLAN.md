Cog shape (mirror `cogs/forum.py`): a `class GalleryCog(commands.Cog)` with `def __init__(self, bot)` that calls the db init, `@commands.Cog.listener()` methods, and a module-level `async def setup(bot): await bot.add_cog(GalleryCog(bot))`. Use `log = logging.getLogger(__name__)` and `import config`.

Detection (BOT-01/D-03, mirrors forum.py `_extract_image_from_message` idiom):
- in `on_message`: return early if `message.channel.id != config.PHOTO_CHANNEL_ID` or `message.author.bot`
- staff gate: `set(r.id for r in getattr(message.author, "roles", [])) & set(config.GALLERY_STAFF_ROLE_IDS)` — community posts ignored ENTIRELY (D-03)
- image attachments = those whose `content_type` is in the allow-list `("image/png","image/jpeg","image/webp")` (excludes gif/video, D-13)
- if any image attachments -> `await message.add_reaction("✅")`

Publish handler (BOT-02, Pattern 1 raw reaction + role gate):
- `on_raw_reaction_add(payload)`: return unless `payload.channel_id == config.PHOTO_CHANNEL_ID`; return if `payload.member is None or payload.member.bot`; role gate on `payload.member.roles ∩ GALLERY_STAFF_ROLE_IDS` (D-01/D-08 trust boundary; self-approval is allowed, D-02)
- `channel.fetch_message(payload.message_id)` (fetch — not guaranteed cached; also works post-restart)
- if `str(payload.emoji) == "✅"` -> `_publish(message)`
- idempotency (D-05): if the message already carries the 🟢 marker placed by the bot (`any(str(r.emoji) == "🟢" and r.me for r in message.reactions)`), silently return — no double publish

`_publish(message)` orchestration:
- collect image attachments (same allow-list, D-13; non-images skipped silently)
- for each, `await attachment.read()` then `await asyncio.to_thread(optimize_to_webp, raw)` (keeps Pillow off the event loop, Anti-Pattern)
- filename per image (D-14): `{YYYYMMDD}-{message.id}-{index}.webp` where date is from `message.created_at` (UTC) and index starts at 1; numerics only — NEVER put caption text in the filename (path-traversal guard)
- caption (BOT-06/D-06): `message.content` trimmed; pass through so github_publish omits the key when empty
- entry `date`: `message.created_at` as ISO 8601 with millisecond precision to match shipped data (`.000Z` style)
- call `github_publish.publish_message(message.id, entries)` (ONE commit, D-16)
- on success: add the 🟢 marker reaction (D-05) and send a reply that auto-deletes after ~60s (D-04, `delete_after=60`) noting the Pages rebuild takes a minute or two (Spanish-first wording)
- on failure: leave error surfacing to 05-04 (D-19) — for now, log and re-raise/return so 05-04's handler can wrap it; do NOT add the 🟢 marker on failure

Loader (`bot.py::setup_hook`): add `await self.load_extension("cogs.gallery")`. bot.py validates required config at startup with `sys.exit(1)` if missing — MIRROR that: fail fast if `GITHUB_PAT`, `WEBSITE_REPO`, or `GALLERY_STAFF_ROLE_IDS` are unset/empty.

Persistence (`core/db.py` pattern): `sqlite3` at `config.DB_PATH`, `conn.row_factory = sqlite3.Row`, `CREATE TABLE IF NOT EXISTS`, `INSERT OR REPLACE`. Add a 1-row `gallery_state` table + `init_gallery_state()` here (the backfill cursor read/scan logic lands in 05-04; this plan just creates the table so `__init__` can call init).

Intents: NO new intent needed — `Intents.default()` + `message_content` (already on) is sufficient; `payload.member` is delivered for guild reactions without the privileged Members intent.
</reference_patterns>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public Discord channel -> publish action | Anyone can post/react in the public photo channel; only staff may trigger a publish |
| staff message content -> gallery.json caption / site render | Free-form text becomes published data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-07 | Elevation of Privilege | non-staff (or a bot) triggers a publish to the public gallery | mitigate | server-side role gate on `on_raw_reaction_add` (`payload.member.roles ∩ GALLERY_STAFF_ROLE_IDS`); skip `.bot`; `on_message` adds ✅ only to staff posts (D-03) |
| T-05-08 | Tampering (stored XSS) | caption from `message.content` rendered on the site | mitigate | caption written by github_publish via `json.dumps` (escaped, valid JSON); site already auto-escapes captions (Phase 4 verified); caption never used in a path |
| T-05-09 | Tampering | path traversal via caption/filename | mitigate | `_build_filename` emits `{YYYYMMDD}-{message.id}-{index}.webp` (digits/hyphens only); caption lives only in the JSON value |
| T-05-16 | Denial of Service | oversized attachment blocks the event loop / spikes memory | mitigate | optimize runs in `asyncio.to_thread`; Pillow `MAX_IMAGE_PIXELS` guard (05-01); optional `attachment.size` cap |
| T-05-SC | Tampering | startup runs with missing secrets/misconfig | mitigate | bot.py `sys.exit(1)` fail-fast when GITHUB_PAT / WEBSITE_REPO / GALLERY_STAFF_ROLE_IDS unset |
</threat_model>
