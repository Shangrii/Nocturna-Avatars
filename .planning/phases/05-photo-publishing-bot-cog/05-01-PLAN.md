Pillow optimize contract (05-RESEARCH.md Pattern 2 — VERIFIED against pillow.readthedocs.io):
- open bytes via `Image.open(io.BytesIO(raw))`
- `ImageOps.exif_transpose` to honour orientation, THEN drop metadata
- convert mode: `P`/`LA` -> `RGBA`; any other non-`RGB`/`RGBA` (e.g. CMYK) -> `RGB` (Pitfall 3)
- `im.thumbnail((1920, 1920), Image.Resampling.LANCZOS)` — downscale-only, preserves aspect (D-12)
- capture post-resize `im.size` -> these become gallery.json `width`/`height` (Phase 4 D-04)
- `im.save(out, format="WEBP", quality=82, method=6)` — NO `exif=` argument, so metadata is stripped (privacy default)
- return `(webp_bytes, width, height)`
- NOTE: `Image.ANTIALIAS` was removed in Pillow 10 — use `Image.Resampling.LANCZOS`.

Attachment allow-list (05-RESEARCH.md, mirrors forum.py `_extract_image_from_message`): only `image/png`, `image/jpeg`, `image/webp` are eligible; `image/gif`, video/* and everything else are excluded (D-13). (The allow-list constant is defined here for reuse; the on_message filter that consumes it lands in plan 05-03.)

gallery.json entry the site consumes (VERIFIED Phase 4): `{ file, caption?, width, height, date }`; `width`/`height` are integers = the STORED (post-resize) pixel dimensions.
