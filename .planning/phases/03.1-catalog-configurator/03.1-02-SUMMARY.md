# Phase 3.1 Plan 02: Cart UI Shells Summary

**One-liner:** Static HTML/CSS shells for CartPill (fixed pill button at z-910) and CartDrawer (right-side slide-in drawer at z-960) with all DOM ids and data-* attributes that cart.ts requires.

## What Was Built

### Task 1 — CartPill.astro

A fixed-position button component with:

- `id="cartPill"`, `hidden` attribute by default — revealed by cart.ts when cart ≥ 1 item
- `class="cart-pill"` scoped to `z-index: 910`, positioned `bottom: calc(clamp(16px, 4vw, 32px) + 44px + 12px)` to float above the existing FloatingCTA (z-900) with 12px gap
- `span.cart-pill__badge[aria-hidden]` with initial text "0" — count updated by cart.ts
- `span[data-cart-label]` with two child spans (`lang="es"` and `lang="en"`) — one hidden based on the `lang` prop; text updated live by cart.ts
- `aria-label` set per `lang` prop for initial state; updated by cart.ts as count changes
- Full CSS: base pill styles, `:hover` translateY(-2px), `:focus-visible` outline
- `.cart-pill[hidden] { display: none }` guard (WR-01 pattern)
- Entrance animation: `.cart-pill--visible` with `@keyframes cart-pill-enter` (0.35s cubic-bezier)
- Exit animation: `.cart-pill--hiding` with `@keyframes cart-pill-exit` (0.2s ease)
- `@media (prefers-reduced-motion: reduce)` disables both keyframe animations

### Task 2 — CartDrawer.astro

Two sibling elements (backdrop + drawer) with:

**Backdrop (`id="cartBackdrop"`):**
- `position: fixed; inset: 0; z-index: 950`
- Fade opacity: 0 → 1 via `.active` class (0.3s ease)
- `aria-hidden="true"`, `hidden` attribute
- `.cart-backdrop[hidden] { display: none }` guard

**Drawer aside (`id="cartDrawer"`):**
- `role="dialog"`, `aria-modal="true"`, `aria-labelledby="cartDrawerTitle"`, `hidden`
- `z-index: 960`, `width: min(420px, 92vw)`, `background: var(--color-ink-raised)`
- Slide-in: `transform: translateX(100%)` closed → `translateX(0)` on `.active` (0.3s ease)
- `.cart-drawer[hidden] { display: none }` guard
- **Header:** title span (`id="cartDrawerTitle"`, bilingual via lang prop) + close button (`data-cart-close`, bilingual aria-label, × SVG icon)
- **Item list:** `ul.cart-drawer__items` with bilingual `aria-label` — empty shell, populated by cart.ts
- **Footer:** total row (`span[data-cart-total]`) + CTA button (`data-cart-ticket`, bilingual "Abrir Ticket / Open Ticket")
- Full CSS for JS-generated `.cart-drawer__item` rows: name, qty, price, remove button

All DOM targeting attributes (`id`, `data-cart-close`, `data-cart-ticket`, `data-cart-total`) match the contracts expected by cart.ts (Plan 03.1-05).

## Deviations from Plan

None — plan executed exactly as written.

The UI-SPEC anatomy showed `class="cart-drawer__cta dc-cart-trigger"` on the drawer CTA, but the plan action section explicitly instructs "Do NOT add 'dc-cart-trigger' class". The plan instruction was followed — only `data-cart-ticket` attribute used for JS targeting.

## Known Stubs

- `CartPill.astro` and `CartDrawer.astro` are not yet mounted in any page (`ServicesPage.astro`). That mount happens in Plan 03.1-04.
- All cart interactivity (show/hide pill, populate drawer, update badge count) is deferred to `cart.ts` (Plan 03.1-05).
- The empty drawer item list will show nothing until cart.ts calls `syncCartUI()`.

## Threat Flags

None. Static HTML/CSS shells — no user input rendered, no dynamic data paths. Consistent with T-03.1-02 accepted risk in the plan threat register.
