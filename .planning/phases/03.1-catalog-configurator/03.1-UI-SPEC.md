## Spacing Scale

Inherited from Phase 03 UI-SPEC. The full scale lives in `src/styles/theme.css @theme --space-*`.

Phase 3.1 usage map (new elements only):

| Token | Value | New Usage in This Phase |
|-------|-------|------------------------|
| `--space-3xs` | 4px | Gap between qty `−`/`+` buttons and count display |
| `--space-2xs` | 8px | Pill badge gap (count number to label text); drawer item row gap |
| `--space-xs` | 12px | Drawer item name/price row horizontal padding |
| `--space-sm` | 16px | Catalog row button padding; drawer header/footer padding; modal inner padding |
| `--space-md` | 24px | Drawer header bottom border to first item; modal title margin-bottom |
| `--space-lg` | 32px | Drawer footer (total + CTA) padding top/bottom |
| `--space-xl` | 48px | Drawer width at mobile (calc basis) |

Exceptions:
- Cart pill touch target: `min-height: 44px; min-width: 44px` (`--touch-min`) — must never collapse smaller
- Qty `−`/`+` buttons: `min-width: 32px; min-height: 32px` (interior control, not a primary CTA)
- Drawer width: `min(420px, 92vw)` — clamps on mobile so it never fills the full viewport
- Backdrop: `inset: 0` (fills entire viewport)

## Z-Index Stacking Order

Existing stack (from `chrome.css`):

| Layer | z-index | Element |
|-------|---------|---------|
| FloatingCTA (Discord) | 900 | `.floating-cta` — bottom-right |
| Nav | 1000 | `.nav` |
| Mobile nav drawer | 1100 | `.nav-links` (mobile) |
| Discord modal overlay | 10000 | `.dc-overlay` |

Phase 3.1 additions (must slot into this stack without collision):

| Layer | z-index | Element | Rationale |
|-------|---------|---------|-----------|
| Cart pill | 910 | `.cart-pill` | Above FloatingCTA (900) but below nav (1000); sits bottom-right at a vertical offset to clear the Discord pill — see positioning below |
| Cart drawer backdrop | 950 | `.cart-backdrop` | Above cart pill (910), below nav (1000) |
| Cart drawer panel | 960 | `.cart-drawer` | Above backdrop (950), below nav (1000) |
| Cart summary modal overlay | 10000 | `.cart-modal-overlay` | Same level as Discord modal; only one open at a time |

**Cart pill positioning (avoids FloatingCTA collision):**

The existing FloatingCTA is at:
```css
position: fixed;
right: clamp(16px, 4vw, 32px);
bottom: clamp(16px, 4vw, 32px);
z-index: 900;
```

The cart pill must be offset vertically above it:
```css
position: fixed;
right: clamp(16px, 4vw, 32px);
bottom: calc(clamp(16px, 4vw, 32px) + 44px + 12px);  /* FloatingCTA height + gap */
z-index: 910;
```

At 375px mobile, this evaluates to: `bottom: calc(16px + 44px + 12px) = 72px`.

## Cart Row Controls — Visual Contract

The `.catalog-row` flex layout extends from Phase 03: `[name left] ···· [price right]`.

Phase 3.1 inserts a cart control zone on the far right. The layout becomes a three-column flex row:

```
[name — flex: 1]  [price — flex-shrink: 0]  [cart control — flex-shrink: 0]
```

**Non-repeatable item (toggle) — HTML structure:**
```html
<li class="catalog-row catalog-row--interactive" data-item-id="{id}">
  <span class="catalog-row__name">{name}</span>
  <span class="catalog-row__price">{price}</span>
  <button class="catalog-row__cart-btn cart-add-trigger"
          type="button"
          data-item-id="{id}"
          aria-label="Agregar {name} / Add {name}">
    Agregar
  </button>
</li>
```

When item is in cart (JS toggles class + label):
```html
<button class="catalog-row__cart-btn catalog-row__cart-btn--added cart-add-trigger" ...>
  Quitar
</button>
```

**Repeatable item (qty) — HTML structure:**
```html
<li class="catalog-row catalog-row--interactive" data-item-id="{id}">
  <span class="catalog-row__name">{name}</span>
  <span class="catalog-row__price">{price}</span>
  <div class="catalog-row__qty" role="group" aria-label="Cantidad {name}">
    <button class="qty-btn qty-btn--dec" type="button" aria-label="Quitar uno">−</button>
    <span class="qty-count" aria-live="polite">0</span>
    <button class="qty-btn qty-btn--inc" type="button" aria-label="Agregar uno">+</button>
  </div>
</li>
```

### Entrance / Exit Animation

- **Entrance:** When cart goes from 0 → 1 items, remove `[hidden]`, then add `.cart-pill--visible` class:
  ```css
  .cart-pill--visible {
    animation: cart-pill-enter 0.35s cubic-bezier(0.16, 1, 0.3, 1) forwards;
  }
  @keyframes cart-pill-enter {
    from { opacity: 0; transform: translateY(12px) scale(0.92); }
    to   { opacity: 1; transform: translateY(0) scale(1); }
  }
  ```
- **Exit:** When cart goes to 0 items, animate out then add `[hidden]`:
  ```css
  .cart-pill--hiding {
    animation: cart-pill-exit 0.2s ease forwards;
  }
  @keyframes cart-pill-exit {
    from { opacity: 1; transform: translateY(0); }
    to   { opacity: 0; transform: translateY(8px); }
  }
  ```
- `prefers-reduced-motion`: skip animations; show/hide instantly with `[hidden]` only.
- Do NOT use `class="reveal"` on the pill — it is JS-controlled, not scroll-triggered.

### Drawer Open/Close Transition

- **Open:** Remove `[hidden]`, then in next frame add `.active`. This matches the WR-01 pattern from `chrome.ts` — display is restored before the transition plays.
- **Close:** Remove `.active`. On `transitionend`, add `[hidden]`.
- Backdrop: Same sequence — remove `[hidden]`, add `.active` to fade in; remove `.active`, add `[hidden]` on `transitionend`.
- Escape key: Closes drawer (and backdrop) — mirror the `chrome.ts` Escape pattern.
- Clicking backdrop: Closes drawer.
- Opening drawer when cart is empty: Blocked by JS (pill is hidden when cart = 0).
- `transition: transform 0.3s ease` on drawer, `transition: opacity 0.3s ease` on backdrop.

### "Copiar" Button State Change

1. User clicks "Copiar selección / Copy selection".
2. JS runs `navigator.clipboard.writeText(plainTextSummary)`.
3. On success: add `.cart-modal__copy--copied` class, change button text to "¡Copiado! / Copied!".
4. After 1500ms: remove class, revert button text.
5. On clipboard failure (denied permission): show a `<pre>` element below the button with the text pre-selected for manual copy. Do not show an alert.

## Component Interaction: Module-Flag Architecture

Cart JS must mirror `chrome.ts` module-flag pattern to prevent listener stacking across ClientRouter navigations.

Required module-level guards in `src/scripts/cart.ts`:

```typescript
// Module-level flags — prevent listener stacking on ClientRouter navigations
let cartDocListenersBound = false;

function initCart(): void {
  // Per-element listeners: safe to re-bind each navigation (fresh DOM nodes)
  bindCartRowControls();
  bindPillClick();
  bindDrawerClose();
  syncCartUI(); // re-render pill/drawer from module-level cart state

  // Document-level listeners: bind ONCE per page lifetime
  if (!cartDocListenersBound) {
    cartDocListenersBound = true;
    bindEscapeKey();      // closes drawer or modal
    bindBackdropClick();  // closes drawer
  }
}

document.addEventListener('astro:page-load', initCart);
```

Cart state persists in module scope across `astro:page-load` calls (intentional — the cart does not reset on soft navigation within the same page session). It resets only on full page reload (no localStorage in Phase 3.1).
