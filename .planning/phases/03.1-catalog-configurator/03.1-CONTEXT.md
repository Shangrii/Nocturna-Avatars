# Phase 3.1: Catalog Configurator - Context

**Gathered:** 2026-07-01
**Status:** Ready for planning

<domain>
## Phase Boundary

An interactive "arma tu paquete" configurator on `/servicios` that lets visitors select individual services 1-by-1 into a client-side cart, see a running price total, and open a Discord ticket with their selection pre-summarized.

**In scope:**
- Populating `services.json` `catalog[]` items with the ~26 services (18 new + 8 existing add-ons redistributed into 4 categories)
- Restructuring the 5 catalog categories into 4 richer ones
- Adding `repeatable` flag to the `services.json` item schema
- Building the cart UI: row add/remove buttons, floating pill counter, drawer panel, modal summary
- Vanilla JS cart engine (client-side, no backend, no framework)

**Out of scope:** Direct bot integration for submitting the cart to a Discord ticket (noted as future idea — integration with cachorabot after Phase 5). Gallery, bot cog, any new page routes.

**Depends on:** Phase 3 (`src/data/services.json`, `CatalogSection.astro`, `ServicesPage.astro`)

</domain>

<decisions>
## Implementation Decisions

### Category structure

- **D-01:** Restructure from 5 categories to **4 well-populated categories**. The existing 5 had too thin a population. New structure:

  | Category ID | Display name (ES / EN) | Contents |
  |-------------|------------------------|----------|
  | `unity` | Unity & Configuración / Unity & Configuration | PhysBones, Face Tracking, Expresiones personalizadas, Optimización de parámetros y menús, Animación AFK personalizada, Rostro personalizado (Face Blendshapes) |
  | `blender` | Blender & Malla / Blender & Mesh | Ajuste de Fitting & Rigging de ropa, Adaptación de blendshapes en ropa externa, Fusión de modelos (quimeras), Creación de blendshapes personalizadas, Aplicación y estilismo de cabello, Outfit adicional, Cabello adicional |
  | `textures` | Texturas & Visual / Textures & Visual | Texturizado personalizado, Tatuajes personalizados, Maquillaje personalizado, Diseño de ojos personalizados, Corrección de iluminación y shaders |
  | `extras` | Extras / Extras | Integración de accesorios (props, toys & VFX), Configuración NSFW, Fotografía y render de presentación, Accesorio extra, Revisión extra, Entrega urgente |

- **D-02:** The old `accessories` category is **dissolved** — its services are redistributed into the 4 categories above.

### Add-ons in catalog

- **D-03:** All 8 existing `packages.addons[]` entries are **added as catalog items** in the appropriate category (see D-01 column). The `packages.addons[]` section in `services.json` may stay for the packages section display, but the same services also appear as catalog items so they are selectable in the configurator. The add-ons block below the package tiers on the services page is **removed** (the catalog configurator replaces it as the way to select individual services).

### Schema extension

- **D-04:** The `catalog[].items[]` schema gains one new optional field:
  ```json
  {
    "name": { "es": "...", "en": "..." },
    "price": "99",
    "repeatable": true
  }
  ```
  `repeatable` is omitted (or `false`) for unique services. When `true`, the cart shows a quantity `+/-` selector for that item. When absent/`false`, the item is a simple toggle (add once / remove).

  **Repeatable items** (can be added multiple times): Outfit adicional, Accesorio extra, Cabello adicional, Revisión extra.

  All other items are toggle (non-repeatable).

- **D-05:** Prices for all catalog items are set to `"99"` (USD, no $ prefix — the component adds the symbol). These are placeholder prices. Staff update the values in `services.json` when the team agrees on final pricing; no code change needed.

### Cart state & engine

- **D-06:** Cart state is **pure client-side JS** — a module-level object (or `Map`) holding `{ itemId → { name, price, qty } }`. No localStorage persistence for now (cart resets on page navigate or refresh). No frameworks — vanilla JS `<script>` in the cart component.

- **D-07:** Cart **coexists with the tier packages** (Penumbra/Umbra/Eclipse) — tiers are "quick picks" above, the catalog configurator is for custom builds below. They do not interact (adding a tier does not pre-fill the cart).

### Cart UI layout

- **D-08:** Cart entry point is a **floating pill button** that appears in the bottom-right corner of the page (distinct from the existing floating Discord CTA in the bottom-left) only when the cart has ≥ 1 item. It shows: `N servicios → Abrir Ticket`. Uses the existing `btn-primary`/`dc-trigger` button pattern with a counter badge.

- **D-09:** Clicking the floating pill opens a **right-side drawer panel**. The drawer:
  - Slides in from the right (`transform: translateX` transition, `0.3s ease`)
  - Has a dark semi-transparent **backdrop overlay** behind it
  - Clicking the backdrop (outside the drawer) closes it
  - Contains: drawer header ("Tu selección" / "Your selection") + list of selected items with individual prices + running total + "Abrir Ticket" CTA button

- **D-10:** The "Abrir Ticket" button that opens the ticket summary modal is located **only inside the drawer** — not on the floating pill itself.

### Selection model

- **D-11:** **Hybrid selection model:**
  - Non-repeatable items: a single `[ Agregar ]` button on the catalog row. Once added → button becomes `[ Quitar ]`. Max 1 of this item.
  - Repeatable items (`repeatable: true`): a `[ − ][ N ][ + ]` quantity control. Min qty = 0 (removes from cart). Starting qty when first added = 1.
  - Row button integrates into the existing editorial row layout (name left, price right) — the add/remove control appears on the far right, price shifts left of it or is hidden in condensed mode.

### Cart summary modal

- **D-12:** When the user clicks "Abrir Ticket" inside the drawer:
  - The drawer closes
  - A modal appears (same modal framework as the existing Discord modal in `chrome.ts`) showing the cart summary
  - Modal contains: a list of selected items + quantities + individual line totals + grand total + a "Copiar selección" button + a "Ir a Discord" button

- **D-13:** The **copy-to-clipboard text** is plain text, suitable for pasting into a Discord ticket:
  ```
  Mi selección de servicios:
  • [Service name] — $[price] USD
  • [Service name] x2 — $[price x2] USD

  Total estimado: $[total] USD
  (Precios sujetos a cotización final)
  ```
  In English (`/en/services`):
  ```
  My service selection:
  • [Service name] — $[price] USD
  • [Service name] x2 — $[price x2] USD

  Estimated total: $[total] USD
  (Prices subject to final quote)
  ```

- **D-14:** After clicking "Copiar selección", the button briefly changes text to "¡Copiado!" / "Copied!" (1.5s) then reverts. The "Ir a Discord" button opens the Discord server link in a new tab (same link used by existing `.dc-trigger` elements).

### Cart row integration with CatalogSection

- **D-15:** `CatalogSection.astro` is extended (or a new `CartCatalogSection.astro` wrapper is created) to support cart controls. The cart state JS is a separate `<script>` module. The cart controls (add/remove buttons, quantity selectors) are rendered in the Astro template as HTML, and their behavior is wired by the cart JS on page load / after Astro page transitions (using `astro:page-load` lifecycle, same pattern as Phase 2 motion controller).

### Claude's Discretion

- Exact CSS for the drawer slide-in animation and backdrop
- Whether to extend `CatalogSection.astro` directly or create a `CartCatalogSection.astro` wrapper
- Exact CSS for the floating pill button (position, z-index layering with existing floating Discord CTA)
- Whether the modal reuses the existing `<dialog>` pattern from `chrome.ts` or creates a new simpler one
- Exact transition timing/easing for row button state change (Agregar → Quitar)
- Z-index stacking order for drawer, backdrop, and floating pill relative to nav

</decisions>

<code_context>
## Existing Code Insights

### What Phase 3 shipped (reusable / integration points)
- `src/data/services.json` — `catalog[]` has 5 categories with `items: []`; Phase 3.1 replaces these with 4 populated categories
- `CatalogSection.astro` — loops `catalog[]`, renders section-tag + editorial rows + EmptyState; the row markup (`<ul class="catalog-rows"><li class="catalog-row">`) is the insertion point for cart buttons
- `ServicesPage.astro` — two `<section>` blocks (packages + catalog); drawer and floating pill are new elements added here

### Existing patterns to follow
- **Page-load JS mounting:** Phase 2 motion controller uses `document.addEventListener('astro:page-load', initMotion)` — cart JS must follow this same pattern for View Transitions compatibility
- **Discord modal:** `chrome.ts` uses a custom `<dialog>` element triggered by `.dc-trigger` class; cart summary modal should use the same `<dialog>` approach
- **Floating CTA:** The existing floating Discord CTA is in the bottom-left (`.floating-cta` in `BaseLayout.astro`). Cart floating pill must use bottom-right to avoid collision
- **Reveal animation:** `class="reveal"` on new elements picked up by GSAP/ScrollTrigger; use on drawer content but NOT on the floating pill or drawer itself (JS-controlled animation, not scroll-triggered)

### Schema extension needed in services.json
Current item schema: `{ name: {es, en}, price: string }`
Extended schema: `{ name: {es, en}, price: string, repeatable?: boolean }`
The `repeatable` field is optional; omitting it equals `false`.

</code_context>

<specifics>
## Specific Behaviors

- Catalog item IDs: each `items[]` entry should get a unique `id` field (e.g., `"face-tracking"`, `"custom-textures"`) so the cart can key items by id. Add `id: string` to the item schema.
- Prices in `services.json` are stored as plain number strings (`"99"`) without `$` or `USD`. The component renders the currency symbol and unit.
- The floating cart pill z-index must be above the drawer backdrop but distinct from the nav (nav is `z-999` per Phase 02.1).
- Empty cart state: when all items are removed from the cart, the floating pill disappears and the drawer closes (or can't be opened).
- The drawer should be accessible: `role="dialog"`, `aria-label="Tu selección / Your selection"`, focus trapped while open, Escape key closes it.
- The existing `.dc-trigger` button class opens the Discord modal; cart controls use a different class (e.g., `.cart-add-trigger`, `.cart-open-trigger`) to avoid conflicts.

</specifics>
