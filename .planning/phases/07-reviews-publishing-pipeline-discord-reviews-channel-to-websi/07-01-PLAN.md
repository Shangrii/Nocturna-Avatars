## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| reviews.json → rendered HTML | Review text originates from Discord clients (untrusted); it crosses into the built site as visible content |
| build-time data → visitor | The section is static-rendered; no runtime user input reaches the visitor here |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|

| T-07-02 | Information disclosure | figcaption attribution | mitigate | `author: null` renders the localized Anonymous fallback (`t.anonymous`); the schema carries no submitter identity, so an anonymous review cannot leak a name here |
| T-07-05 | Denial of service | long review text layout | accept | Text is capped ~500 chars at the Discord modal (07-04); cards grow gracefully with no clamp — a 500-char card is a layout, not a hazard |
| T-07-SC | Tampering (supply chain) | npm dependencies | accept | This plan adds ZERO npm dependencies (UI-SPEC L124); no install task exists, so no package-legitimacy gate is triggered |
</threat_model>
