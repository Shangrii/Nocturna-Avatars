## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| bot host → GitHub API | Cross-repo write authenticated by a fine-grained PAT crosses here |
| review entry dict → reviews.json | Untrusted client text is serialized into a repo file (rendered escaped downstream, 07-01) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-04 | Spoofing/Tampering | cross-repo commit auth | mitigate | Reuse the live fine-grained PAT (Contents: read/write, single repo Shangrii/Nocturna-Avatars); read from `config.GITHUB_PAT` at call time, place ONLY in the Authorization header via `_headers()`, never interpolate into log text — asserted by a caplog test |
| T-07-02 | Information disclosure | author field serialization | mitigate | The transport is dumb about identity: it writes the `author` value it is handed. `author: null` is preserved verbatim; anonymity is enforced upstream (07-04) and the transport never derives/logs a name |
| T-07-05 | Denial of service | unbounded retry / stuck lock | mitigate | Reuse `_TIMEOUT` on every request and the bounded `_MAX_ATTEMPTS` retry with backoff; a network stall raises `GitHubPublishError` instead of holding `_commit_lock` forever |
| T-07-REG | Tampering (regression) | shared transport internals | mitigate | Changes to `_fetch_gallery`/`_commit_with_retry` are backward-compatible (extraction + default arg); the full `test_github_publish.py` suite is a required passing gate |
| T-07-SC | Tampering (supply chain) | pip dependencies | accept | No new pip packages — reuses stdlib + `requests` + `config` already present; no install task, no legitimacy gate |
</threat_model>
