# Phase 7 — UI Design Contract

> Visual and interaction contract for the website **Testimonials section** (the only website-side UI in this phase). The Discord `ReviewsCog` side has no website UI and is out of scope here. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**UI scope:** one new landing-page section (`src/components/sections/Reviews.astro`, name at planner discretion) that renders `src/data/reviews.json` at build time — mirroring how `FeaturedGallery.astro` renders `gallery.json`. Everything reuses the existing **Refined Street Editorial** system (Phase 02.1); this phase introduces **no new tokens, fonts, or dependencies**.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Astro static + Tailwind v4 CSS-first `@theme`; hand-rolled component CSS). shadcn gate **not applicable** — not a React/Next/Vite app. |
| Preset | not applicable |
| Component library | none (native Astro components + shared CSS classes in `src/styles/`) |
| Icon library | none — inline SVG only (no icon dependency). This section needs at most a decorative quotation glyph (CSS/`::before` or inline SVG). |
| Font | Space Grotesk (display/headings), A Another Tag → Permanent Marker (graffiti accent), Inter (body), Space Mono (labels/meta). Loaded globally; do not add fonts. |

**Source of truth for all tokens:** `src/styles/theme.css` `@theme` block. Reuse existing utility/`var(--…)` tokens; do not hardcode hex or px.

## Spacing Scale

Reuse the existing 8-point scale tokens from `theme.css` (do not introduce new values):

| Token | Value | Usage in this section |
|-------|-------|-------|
| `--space-3xs` | 4px | Author/date micro-gap |
| `--space-2xs` | 8px | Meta line gaps, inline chips |
| `--space-xs` | 12px | Quote-glyph offset |
| `--space-sm` | 16px | Card inner spacing (tight) |
| `--space-md` | 24px | Card padding, header title→tag gap |
| `--space-lg` | 32px | Card padding (comfortable), grid gap fallback |
| `--space-xl` | 48px | Card vertical padding |
| `--space-2xl` | 64px | Section-internal block breaks |
| `--space-3xl` | `clamp(60px,10vw,120px)` | Section vertical padding (via `--section-pad`) |

**Card grid gap:** use the established editorial hairline-grid idiom — `gap: 1px` over a `--color-border` background (as `.cards` / `.about-features` do) so testimonial cards separate with 1px rules, not open gaps. Exceptions: none. Touch targets (any link) ≥ `--touch-min` (44px).

## Typography

Reuse `theme.css` type tokens. No new sizes.

| Role | Token / Size | Weight | Line Height | Applies to |
|------|------|--------|-------------|------------|
| Section tag | `--font-mono` `clamp(11px,1.6vw,14px)`, `letter-spacing:0.32em`, uppercase | 400 | `--lh-label` (1.4) | `.section-tag` eyebrow (localized) |
| Section title | `--font-display` `clamp(30px,6vw,64px)`, `letter-spacing:-0.02em`, uppercase | 700 | 0.95 | `.section-title` (localized) |

Two weights only (400 body/labels, 700 display) — matches the system. Review text is **never** italicized wholesale or restyled per emphasis; render as plain paragraph text.

## Color

Reuse the Refined Street Editorial ink/paper rhythm. No new colors.

| Role | Token (value) | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-ink` `#0a0c14` | Section field when placed as `.section` (ink); off-white text on it |
| Secondary (30%) | `--color-ink-raised` `#10131e` (ink field) / `--color-paper` `#11141f` (paper field) | Testimonial card surface — raised navy on ink sections, dark espresso-charcoal on `--section--surface` |
| Accent (10%) | `--color-red` `#c0192c` (+ AA-safe `--color-red-on-ink` `#e84a5e` / `--color-red-on-paper` `#c0192c`) | See reserved list below |
| Destructive | not applicable | No destructive UI on the website. Unpublish/remove is entirely Discord-side (staff 🌙); nothing on the site deletes data. |

**Accent reserved for (one accent per section, D-09):**
1. The `.section-tag` eyebrow (mono, AA-safe red per surface).
2. A single decorative quotation glyph per card (the card's one red mark).
3. The hairline top-rule that draws in on card hover (`transform:scaleX` red rule, as `.card::before` does) — optional.

Red is **never** applied to the review body text, author name, or date. Body text uses `--color-white` / `--color-white-dim` on ink, `--color-ink-on-paper` on paper — all AA-verified in the existing system.

## Copywriting Contract

All section chrome (tag, title, author-fallback, date) is localized through the existing i18n dictionary system — add a `reviews` key to `src/i18n/pages.json` under both `es` and `en` (mirrors the `teaser`/`gallery` pattern). **Review body text is user-generated and rendered VERBATIM in its original language — never translated** (D: "render verbatim in its original language"). Astro auto-escaping only; never `set:html`.

| Element | Copy |
|---------|------|
| Section tag (ES / EN) | `Reseñas` / `Reviews` |
| Section title (ES / EN) | `Lo que dicen nuestros clientes` / `What our clients say` |
| Anonymous author fallback (ES / EN) | `Anónimo` / `Anonymous` (rendered when `author: null` — the submitter's real name must never appear anywhere for anonymous reviews) |
| Date format | Localized month + year only via `Intl.DateTimeFormat(lang, { month: 'long', year: 'numeric' })` (privacy-light; avoids exposing exact submission day). Showing the date at all is **Claude's discretion** — recommended on. |
| Empty state | **Section is omitted entirely** when `reviews.json` is `[]` — no placeholder block. (See Empty-state behavior below.) |
| Error state | not applicable at runtime — build-time render; a malformed `reviews.json` is a developer/build-time failure, not a visitor-facing error surface. |
| Destructive confirmation | not applicable — no destructive action exists on the website |
| Primary CTA | none dedicated. The persistent floating **"Abrir Ticket" / "Open a Ticket"** conversion anchor (Phase 02.1) stays visible; testimonials are social proof adjacent to it. A closing `.link-arrow` is optional (discretion). |

## Interaction & Layout Contract

- **Render model:** static, build-time. `import reviewsData from '../../data/reviews.json'`. **No client-side JS required** for this section (unlike the gallery lightbox). Sort newest-first by `date`; slice to the newest **9** (within the decided ~8–10 range — planner may pick any value in 8–10; 9 gives a clean 3×3 on desktop). Exact cap is Claude's discretion within 8–10.
- **Data contract consumed:** `reviews.json` = array of `{ id: string, author: string | null, text: string, date: string (ISO 8601) }`. `author: null` ⇒ render the localized Anonymous fallback. `id` is the Discord message id (used as the stable key; not displayed).
- **Card anatomy:** decorative red quote glyph → review body (Inter 16px/1.7, verbatim, escaped) → hairline `--card-divider` → meta line (`— {author}` in Space Mono + localized month/year). Card surface = `--color-ink-raised` on ink sections / `--color-paper` on `--section--surface`; 0px radius; hairline border; matches `.card` idiom.
- **Grid:** `grid-template-columns: repeat(auto-fit, minmax(min(300px,100%), 1fr))`; `gap:1px` on a `--color-border` background (editorial hairline grid). Collapses to 1 column on mobile. Mirrors `.cards` / `.about-features`.
- **Long text:** modal input is capped ~500 chars (Discord side), so cards must lay out gracefully up to ~500 chars — no truncation/clamp needed; the card grows. Do not add "read more".
- **Reveal-on-scroll:** add the existing `.reveal` class so the section participates in the shared GSAP scroll choreography; must respect `prefers-reduced-motion` (already handled globally). No bespoke animation.
- **Section surface / placement:** wire into the landing composition (`src/pages/index.astro` + `[lang]` variants) so it continues the ink↔paper alternation. Whether it lands as `.section` (ink) or `.section--surface` (paper) is **Claude's discretion**, decided by its neighbors to preserve the rhythm. Use `.section--rule` hairlines for the top/bottom edge like sibling sections.
- **Empty-state behavior:** when `reviews.json` is empty, **the component renders nothing** (early `return null` / no markup) rather than a branded EmptyState block. Rationale: an empty or "coming soon" social-proof block weakens the conversion path; absence is cleaner than a placeholder. This deliberately diverges from `FeaturedGallery`/services EmptyState usage — documented per CONTEXT ("renders nothing **or** collapses when empty"). `reviews.json` ships committed as `[]` so builds never break.
- **Accessibility:** each testimonial should be a `<figure>` with the review in `<blockquote>` and the attribution in `<figcaption>` for correct semantics. Per-card `lang` attribute is **omitted** because each review's language is not stored in the schema (would require guessing) — noted as a known limitation; if a future schema adds a language field, set `lang` per card then.
