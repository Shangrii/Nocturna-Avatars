<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Discord reactor → publish action | A ✅/🌙 reaction in the public reviews channel can trigger a cross-repo commit — the staff role gate is the trust boundary |
| Discord client message → reviews.json | Untrusted client review text crosses into a repo file (escaped at render, 07-01) |
| bot host → GitHub | Cross-repo write via the fine-grained PAT (owned by 07-02) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-03 | Elevation of privilege | on_raw_reaction_add / _reconcile | mitigate | `_is_staff(payload.member)` gate on REVIEWS_STAFF_ROLE_IDS on every live reaction; backfill resolves reactors via `_reaction_by_staff` + `_resolve_member` (fetch_member on cold cache) so a non-staff ✅/🌙 during downtime never publishes |
| T-07-02 | Information disclosure | _review_author_and_text / _publish entry | mitigate | For plain client messages the author is the client's own display name (they typed publicly); the anonymous path is added in 07-04. The entry carries no other identity; text is escaped downstream |
| T-07-06 | Denial of service (mass-remove) | _reconcile_orphans | mitigate | Only a discord.NotFound removes an entry; any other error (rate-limit/outage) leaves entries untouched — a transient failure can never wipe the live reviews |
| T-07-05 | Denial of service | publish failure surfacing | mitigate | Transport failures raise GitHubPublishError (bounded retries in 07-02); the cog surfaces ⚠️ + a persistent reply and never adds 🟢, so state stays recoverable |
| T-07-SC | Tampering (supply chain) | pip dependencies | accept | No new pip packages — discord.py + requests already present; no install task, no legitimacy gate |
</threat_model>
