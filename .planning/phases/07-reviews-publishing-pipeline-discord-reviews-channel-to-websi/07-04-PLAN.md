## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Modal submitter → bot review embed | Anyone (public embed) can submit; the submitter's identity must be contained on the named path and ELIMINATED on the anonymous path |
| bot review embed → publish pipeline | The embed is the source the staff-gated pipeline (07-03) publishes; author resolution happens here |
| command invoker → posting the panel | Only staff may post the collection embed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-02 | Information disclosure | anonymous modal / embed build | mitigate | The anonymous branch never writes `interaction.user`'s name/id/mention into the embed; `_review_author_and_text` maps "no embed author" → author None → `author: null` in reviews.json; asserted absent by grep + unit tests |
| T-07-03 | Elevation of privilege | collection-panel command | mitigate | The command is gated to `_is_staff` (REVIEWS_STAFF_ROLE_IDS) or DISCORD_USER_ID; a non-staff invoker gets "Sin permisos." Publication itself remains staff-✅-gated (07-03) regardless of who submitted |
| T-07-01 | Injection (XSS) | modal text → embed → reviews.json | mitigate | Review text is treated as data end-to-end: never `set:html` (website 07-01 escapes); the modal caps input at 500 chars; the embed shows it as content, Discord does not execute it |
| T-07-07 | Tampering (stale-view spoof) | persistent view custom_ids | mitigate | Stable custom_ids + `bot.add_view` re-registration; buttons only OPEN a modal (no privileged action), and any resulting review still passes the staff ✅ gate before publishing |
| T-07-SC | Tampering (supply chain) | pip dependencies | accept | No new pip packages — discord.ui.Modal/View ship with the already-present discord.py; no install task, no legitimacy gate |
