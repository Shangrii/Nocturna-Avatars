<objective>
Wire the existing packages section (tiers + add-ons) in `ServicesPage.astro` and `PackagesSummary.astro`
to read directly from `src/data/services.json` instead of the per-lang `packages.json` dictionary.
Then retire `packages` from the `ui.ts` registry.

The key transformation: `services.json` uses the bilingual-per-entry `{es, en}` schema, so each
parent component resolves `tier.tier[lang]`, `tier.subtitle[lang]`, `tier.oneLiner[lang]`, and
`feature.text[lang]` into flat strings before passing them to `PackageCard`. `PackageCard` itself
does not change — it still receives flat resolved strings.

UI-copy strings that were in `packages.json` but aren't data (advanceNote, usd, popularBadge,
ctaTicket/ctaLabel, summaryCtaAll, addonsTitle) move to `pages.json` under the existing
`servicios` / `services` keys. This keeps the clean separation: `services.json` = data,
`pages.json` = copy labels.

After this plan: visiting `/es/servicios` or `/en/services` shows all 3 packages with real data
from `services.json`. The catalog section still shows the existing placeholder (wired in Plan 03).
</objective>

<!-- PackageCard.astro interface (unchanged) -->
interface Tier {
  id: string; tier: string; name: string; subtitle: string; price: string;
  oneLiner: string; featured: boolean; features: {text: string; highlight: boolean}[];
}
interface Props {
  tier: Tier; usd: string; advanceNote: string; popularBadge: string;
  ctaLabel: string; condensed?: boolean;
}

<!-- Lang resolution pattern -->
Given lang: Lang and a tier object from services.json, resolve before passing to PackageCard:
  const resolvedTier = {
    ...tier,
    tier: tier.tier[lang],
    subtitle: tier.subtitle[lang],
    oneLiner: tier.oneLiner[lang],
    features: tier.features.map(f => ({ text: f.text[lang], highlight: f.highlight }))
  };
