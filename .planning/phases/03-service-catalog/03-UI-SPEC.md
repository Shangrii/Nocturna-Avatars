## Spacing Scale

Tokens live in `src/styles/theme.css @theme` as `--space-*`. Use Tailwind spacing classes where
possible; reference CSS custom properties in stylesheet rules.

| Token | Value | Usage |
|-------|-------|-------|
| 3xs | 4px (`--space-3xs`) | Icon gaps, inline micro-padding |
| 2xs | 8px (`--space-2xs`) | Compact badge padding, tight inline gaps |
| xs | 12px (`--space-xs`) | Tag padding, pill labels |
| sm | 16px (`--space-sm`) | Default element spacing, button padding |
| md | 24px (`--space-md`) | Between tag and heading, between heading and rows |
| lg | 32px (`--space-lg`) | Between catalog category blocks |
| xl | 48px (`--space-xl`) | Card internal padding, major section gaps |
| 2xl | 64px (`--space-2xl`) | Between major sections within a page |
| 3xl | clamp(60px, 10vw, 120px) (`--space-3xl` / `--section-pad`) | Outer section vertical padding |

Exceptions:
- Touch targets: minimum 44px (`--touch-min`) for all interactive elements (CTA buttons, row hover areas)
- Editorial row height: minimum 44px to satisfy touch target floor at mobile
- Hairline rules: exactly 1px — never a spacing token

## Color

Source: Phase 02.1 D-07, D-08; `src/styles/theme.css @theme`.

All surfaces in Phase 3 are DARK. "Paper" in this project is a dark warm espresso-charcoal
(`#11141f`), not a bright field. The editorial rhythm is warm-dark vs. cool-dark.

| Role | Token | Hex | Usage |
|------|-------|-----|-------|
| Dominant 60% — Ink surface | `--color-ink` / `bg-ink` | `#0a0c14` | Packages section, cards, default section background |
| Secondary 30% — Paper surface | `--color-paper` | `#11141f` | Catalog section background (alternates with ink) |
| Ink raised | `--color-ink-raised` | `#10131e` | Card interior, addon tiles |
| Foreground on ink | `--color-paper-on-ink` | `#f0eae4` | Text on ink surfaces |
| Foreground on paper | `--color-ink-on-paper` | `#f0eae4` | Text on paper surfaces |
| Accent 10% | `--color-red` / `text-red` | `#c0192c` | See reserved-for list below |
| Accent on ink (AA safe) | `--color-red-on-ink` | `#e84a5e` | Small red text on ink backgrounds |
| Accent on paper (AA safe) | `--color-red-on-paper` | `#c0192c` | Small red text on paper backgrounds |
| Muted foreground | `--color-white-dim` | `#9a9198` | Secondary text, feature list items, subtitles |
| Hairline border | `--color-border` | `color-mix(in srgb, #ffffff 6%, transparent)` | 1px separators, card outlines |
| Destructive | `--color-red` | `#c0192c` | No destructive actions in this phase |

**Accent (`--color-red`) reserved exclusively for:**
1. Section-tag red accent line (the horizontal rule above each `<span class="section-tag">`)
2. Section-tag text color (via `--color-red-on-ink` or `--color-red-on-paper`)
3. Featured package card border (`inset 0 0 0 1px var(--color-red)`) + `::before` reveal bar
4. "Cotizar" price label text color (see Cotizar Styling below)
5. The "Más popular" / "Most popular" badge text inside the Eclipse card
6. The `✦` bullet marker in highlighted feature list items
7. Card CTA button background (`--color-red` fill; darkens to `--color-red-dark` on hover)
8. The `card-popular` badge text on Eclipse card
9. Add-ons section title text (`addons-title` element)

Red is NOT used for: row backgrounds, section backgrounds, heading text, body text, borders in
non-featured catalog rows, or any decorative fills in the catalog section.

**Section surface assignments:**
- Packages section (tiers + add-ons): INK (`bg-ink`, `color: var(--color-paper-on-ink)`)
- Catalog section (CatalogSection.astro): PAPER (`.section--surface`, `background: var(--color-paper)`)
- This alternates the established ink → paper rhythm; catalog sits below packages exactly as in the
  existing two-section layout in `ServicesPage.astro`.

## Section-Tag Pattern

Every category header in CatalogSection uses the exact existing `.section-tag` pattern:

```html
<div class="section-header reveal">
  <span class="section-tag">{category.category[lang]}</span>
  <h2 class="section-title">{category.category[lang]}</h2>
</div>
```

- `<span class="section-tag">` — Space Mono, clamp(11px, 1.6vw, 14px), uppercase, 0.32em tracking,
  color `--color-red-on-paper` (because catalog is `.section--surface`)
- The existing `.section--surface .section-tag` rule in `sections.css` already handles the color
  flip — no new CSS needed for tag color
- Category heading below the tag: Space Grotesk 700, clamp(24px, 4vw, 44px), uppercase, -0.02em,
  line-height 0.95, color `--color-ink-on-paper`
- Spacing: `margin-bottom: var(--space-md)` between tag and heading (existing `.section-tag` rule)
- The `section-header` block uses `margin-bottom: clamp(40px, 6vw, 72px)` before the row list
  (existing `.section-header` rule)
- Add `class="reveal"` to the `section-header` div — GSAP/ScrollTrigger picks it up automatically

## Editorial Row Layout

Source: Phase 03 D-08, D-09.

Each service item in a category renders as a single horizontal row:

**Anatomy:**
```
[Service name — left]  ·····hairline·····  [Price or "Cotizar" — right]
────────────────────────────────────────── 1px hairline separator
[Next service]                             [Price]
────────────────────────────────────────── 1px hairline separator
```

**Row CSS contract:**
- Container: `display: flex; justify-content: space-between; align-items: center`
- Min height: 44px (touch target floor, `--touch-min`)
- Padding: `var(--space-sm) 0` (16px top/bottom, no horizontal padding — rows sit inside the
  catalog section's page gutter)
- Separator: `border-bottom: 1px solid color-mix(in srgb, var(--color-ink-on-paper) 14%, transparent)`
  (paper-surface version of `--color-border`)
- First row: also has `border-top: 1px solid ...` matching same formula (closes the top of the list)
- No row background — transparent on the paper surface

**Service name (left column):**
- Font: Inter, 16px, weight 400
- Color: `var(--color-ink-on-paper)` (off-white on paper)
- No transform, normal tracking

**Price value (right column):**
- Font: Space Mono, 16px, weight 400, `font-variant-numeric: tabular-nums`
- Color: `var(--color-ink-on-paper)` for real price strings (e.g. "+$5 USD")
- Tracking: 0.04em
- No transform

**No description field.** Name + price only per D-09.

## "Cotizar" Styling

Source: Phase 03 D-05, specifics note.

When `item.price === "cotizar"` (case-insensitive sentinel in `services.json`), the component
renders the string "Cotizar" in both ES and EN (word is the same).

Exact rendering:
- Text: `"Cotizar"` (capitalize first letter in output; `"cotizar"` is the JSON sentinel)
- Font: Space Mono, 16px, weight 400, `font-variant-numeric: tabular-nums`
- Color: `var(--color-red-on-paper)` — the AA-safe brand red on the paper surface
- No italic, no strikethrough, no additional decoration
- Rationale: red signals "call for pricing" without false urgency; tabular mono keeps column
  alignment identical to real price strings; on paper surface `--color-red-on-paper` (#c0192c)
  achieves the required contrast (≥4.5:1 on `--color-paper` #11141f — verified in Phase 02.1)

## Featured Package Card (Eclipse)

Source: `PackageCard.astro` `featured: true` path; `sections.css` `.card.featured` rules.

The Eclipse tier has `featured: true` in `services.json`. Visual treatment — already implemented
in `sections.css`, carry forward unchanged:

- Inset border: `box-shadow: inset 0 0 0 1px var(--color-red)` (replaces hairline-border outline)
- Top rule: `::before` element with `background: var(--color-red); transform: scaleX(1)` (always
  visible, unlike non-featured cards where it only appears on hover)
- "Más popular" / "Most popular" badge: rendered by `card-popular` div; Space Mono 9px, uppercase,
  0.24em tracking, color `var(--color-red-on-ink)` (packages section is ink)
- Card background: `--color-ink-raised` (same as non-featured; the border + rule carry the weight)
- No scale transform, no glow, no shadow beyond the inset border — refined not maximalist

PackageCard.astro requires no visual changes in Phase 3 — only its data source changes (from
`packages.json` i18n dict to `services.json` direct import). The existing `.card.featured` CSS
already handles the treatment.

## Hover / Interaction States

Source: Phase 02.1 D-09 (refined not maximalist); Phase 03 D-08.

### Editorial rows
- Hover state: subtle background tint — `background: color-mix(in srgb, var(--color-ink-on-paper) 4%, transparent)`
- Transition: `background 0.2s ease`
- No transform lift, no color change on name or price text
- Cursor: default (rows are not links; they are display-only)
- Rationale: a faint hover acknowledges interaction without implying clickability

### Package cards (existing behavior, preserved)
- Non-featured cards: `::before` red top-rule draws in via `scaleX(0 → 1)` on hover (0.5s transition)
- Featured (Eclipse): top-rule always visible; no additional hover state needed
- CTA button: `background: var(--color-red-dark)` on hover (0.2s); no transform

### CTA buttons (EmptyState)
- `.btn-primary.dc-trigger`: existing button styles; inherits from global button rules
- Min height: 44px (`--touch-min`)
- Focus ring: visible (inherited from global, Phase 02.1 D-10 removes cursor but keeps focus rings)

### Scroll reveal
- Add `class="reveal"` to: each category `section-header`, each row-list container
- GSAP/ScrollTrigger picks these up automatically (Phase 2 motion controller)
- `prefers-reduced-motion`: honored by the existing ScrollTrigger setup; no additional handling needed

## Mobile Layout (375px)

Source: Phase 02.1 quality bars (responsive at 375/768/1024/1440, no horizontal scroll).

### Editorial rows at 375px
- Row layout stays `flex; justify-content: space-between` — both columns fit on one line at 375px
  because name and price are short strings (no descriptions)
- If a service name is very long (>30 chars), it wraps; price stays pinned right with `flex-shrink: 0`
- Row padding: `var(--space-sm) 0` (16px) — unchanged at mobile
- No stacking layout needed; the two-column row is legible at 375px

### Package cards at 375px
- `.cards` grid: `auto-fit, minmax(min(280px, 100%), 1fr)` collapses to a single-column stack
  (existing behavior)
- Cards fill full width; internal padding `var(--space-xl) var(--space-lg)` reduces to
  `var(--space-xl) var(--space-sm)` at narrow width via existing responsive card rules
- No horizontal scroll at 375px — existing card layout handles this

### Category section headers at 375px
- `section-header` uses `padding: 0 var(--page-gutter)` where `--page-gutter: clamp(20px, 4vw, 48px)`
  (= 20px at 375px) — safe margins maintained
- Section title wraps naturally; `line-height: 0.95` on display type remains visually correct when
  wrapped

### Touch targets
- All interactive elements (CTA buttons, Discord trigger) have `min-height: 44px` (`--touch-min`)
- Editorial rows have `min-height: 44px` to meet the touch floor even though they are non-clickable
  (future-proofing if rows become links in Phase 4+)

## Catalog Section Container

The CatalogSection renders inside the existing second `<section>` in `ServicesPage.astro`:

```html
<section class="section section--surface section--rule">
  <!-- section-header (catalogTag + catalogTitle) remains as-is -->
  <!-- CatalogSection.astro replaces the EmptyState placeholder -->
</section>
```

- Class: `section section--surface section--rule`
- `section--surface`: applies paper background (`--color-paper`), flips text to `--color-ink-on-paper`
- `section--rule`: adds 1px `--color-border` rules at top and bottom of section
  (paper variant: `color-mix(in srgb, var(--color-ink-on-paper) 14%, transparent)`)
- Max-width for catalog content: `max-width: 1000px; margin: 0 auto; padding: 0 var(--page-gutter)`
  — matches `.section-header` and `.addons` width to keep the page column consistent
- Between each category block: `margin-bottom: var(--space-lg)` (32px)

## Data Rendering Rules

These rules translate the `services.json` schema into UI behavior.

| Condition | Render |
|-----------|--------|
| `item.price === "cotizar"` | "Cotizar" in `--color-red-on-paper`, Space Mono |
| `item.price` is any other string | Price string verbatim in `--color-ink-on-paper`, Space Mono |
| `category.items.length === 0` | `<EmptyState>` with bilingual props (see above) |
| `category.items.length > 0` | Editorial row list (name left, price right, hairline separators) |
| `tier.featured === true` | Featured card treatment: inset red border + always-visible red top rule + `card-popular` badge |
| `tier.featured === false` | Standard card: red top rule appears only on hover |
| `tier.price` string | Rendered in `card-price` (Space Mono, clamp 34–44px) |

**Bilingual rendering:** All string fields from `services.json` are `{ es: string, en: string }`
objects. Components receive the active `lang` and read `field[lang]`. The `name` field on package
tiers is a proper noun (no translation object) — render as-is.

## Accessibility Contract

Source: Phase 02.1 quality bars; WCAG AA.

| Requirement | Implementation |
|-------------|----------------|
| Text contrast ≥4.5:1 | Off-white on ink: 13.5:1 ✓; off-white on paper: 13.95:1 ✓; red-on-paper on paper: ≥4.5:1 ✓ (verified Phase 02.1) |
| Touch targets ≥44px | All CTA buttons `min-height: var(--touch-min)`; editorial rows min-height 44px |
| Visible focus rings | Inherited from global styles (Phase 02.1 D-10 — custom cursor removed, focus rings kept) |
| Keyboard navigation | Discord modal trigger is a `<button>`; all CTAs are `<button>` elements; no click-only divs |
| `prefers-reduced-motion` | GSAP/ScrollTrigger setup from Phase 2 respects this — `reveal` class items animate only when motion is allowed |
| No horizontal scroll | Flex rows with `flex-shrink: 0` on price; grid cards with `min(280px, 100%)` column floor |
| Images | No new images in Phase 3 |
| `alt` text | No new images |
| Semantic markup | Each category = `<section>` or `<div role="group">`; row list = `<ul>` with `<li>` items |

**Row list markup (semantic):**
```html
<ul class="catalog-rows" aria-label="{category.category[lang]}">
  <li class="catalog-row">
    <span class="catalog-row__name">{item.name[lang]}</span>
    <span class="catalog-row__price">{priceDisplay}</span>
  </li>
  <!-- … -->
</ul>
```
